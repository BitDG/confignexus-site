# 12 组件需求说明书模板

> **这份文档是干什么的**
> 想做一个新组件时，**先复制这份模板填一遍**，把"要做成什么样"讲清楚，再交给做组件的人（开发者或 AI）。
> 填表的人**不需要懂代码**——第 1~5 部分是给提需求的人填的；第 6 部分"技术登记"是给开发者填的，提需求时留空即可。
>
> **怎么用**：
> 1. 复制本文件，改名成 `需求-你的组件名.md`，放进 `dev/` 或发给开发者。
> 2. 把下面每个 `____` 填上，勾掉用得到的 `[ ]`，删掉用不上的行。
> 3. 填完通读一遍"第 5 部分 验收标准"——这是将来判断"组件做完没"的唯一依据，含糊就会扯皮。
>
> 怎么实现由开发者照着同目录的 `00`~`11` 技术规范做，需求方不用管。

## 第 1 部分 · 基本信息【需求方填】

| 项目 | 内容 |
|------|------|
| **组件中文名** | ____（例：背包系统） |
| **一句话作用** | ____（例：把表格里的道具配置变成可视化的背包界面，方便策划检查） |
| **给谁用** | ____（例：策划 / 美术 / 测试） |
| **解决什么问题** | ____（不做这个组件，现在他们怎么干、痛在哪） |

**组件类型**（二选一，不确定就让开发者判断）：

- [ ] **预览型（preview）** — 只看不改，把表格数据漂亮地展示出来（背包、抽卡、对话都是这种）
- [ ] **编辑型（editor）** — 能在组件里直接画/改，再写回去（地图编辑器是这种）

| 项目 | 内容 |

| **工作表名** | ____（例：道具表） |
| **数据从第几行开始** | ____（前几行通常是表头，例：第 4 行起是真数据） |

**字段 → 列对应关系**（左边是组件要用的信息，右边是它在表格的第几列）：

| 组件要用的字段 | 在表格的列 | 备注 |
|----------------|-----------|------|
| id（唯一编号） | A | 必填 |
| 名称 | B | |
| ____ | ____ | |
| ____ | ____ | |

> 不知道列字母没关系，写中文列标题也行（例：「图标=道具图标列」），开发者会对照表头转换。

## 第 3 部分 · 界面与功能【需求方填】

描述组件打开后长什么样、能点什么。**每条尽量写成"用户能看到 / 能点到的东西"**，别写技术词。能画个草图（哪怕手画拍照）最好。

**顶栏**（最上面一条）：
- [ ] 标题文字：____

- [ ] ____

**主体区**（中间最大那块）：

- [ ] 点某一项会：____（例：右侧弹出详情）
- [ ] 编辑区（编辑型才有）：____（例：可拖拽的地图格子）

**按钮 / 操作**：
- [ ] ____（例：「同步数据」从表格刷新最新内容）
- [ ] ____（例：「设置映射」配置读哪张表）
- [ ] ____

## 第 4 部分 · 多语言【需求方填】

组件名会显示在「组件」菜单里，**软件切语言时组件名要跟着变**。把四种语言都写上（至少写中英）：

| 语言 | 组件名 |
|------|--------|
| 简体中文 zh-CN | ____ |
| English en-US | ____ |
| 日本語 ja-JP | ____ |
| 한국어 ko-KR | ____ |

> 界面内部的其它文字（按钮、标题）要不要也做多语言？ [ ] 要 [ ] 暂时只做中文
> 做法见 `11_多语言支持规范.md`。

## 第 5 部分 · 验收标准【需求方填，开发者补充】

**"满足下面每一条才算做完"** —— 将来照这个清单逐条点，点不出来就是没做完。

**通用必过项**（所有组件都要，照抄即可）：
- [ ] 在主程序「组件」菜单里能看到这个组件，点一下能打开窗口
- [ ] 软件切到英文 / 日文，组件名跟着变成对应语言
- [ ] 点「同步数据」后，组件里的内容跟表格一致
- [ ] 关掉再开，之前配的映射 / 设置还在（不用每次重配）

**本组件特有项**（按第 3 部分功能逐条写"怎么算对"）：
- [ ] ____（例：道具表里有 99 个道具，背包里就显示 99 个卡片，名称数量都对）
- [ ] ____（例：点某个道具，右侧详情显示它的描述文字）
- [ ] ____

## 第 6 部分 · 技术登记【开发者填，需求方留空】

开发者开工时把 `metadata.json` 的关键字段在这里登记一遍，方便复查。字段含义见 `00_组件开发总览.md`。

| 字段 | 值 | 说明 |
|------|-----|------|
| `name` | ____ | 目录名，下划线命名，如 `mybag_app` |
| `toolType` | ____ | 全局唯一，如 `mybag` |
| `componentType` | `preview` / `editor` | 对应第 1 部分选的类型 |
| `icon` | ____ | Lucide 图标名，见 https://lucide.dev/icons |
| `devPort` | ____ | **不能跟下表已占用的撞** |
| `displayNames` | 见第 4 部分 | zh-CN / en-US / ja-JP / ko-KR 四个都要填 |
| `sync.displayName` | ____ | 同步按钮文字，如「背包同步」 |
| `sync.buttonColor` | ____ | 按钮渐变色，见 `07_UI组件规范.md` |

**已占用的 devPort（新组件请从 5178 往后取）**：

| 端口 | 组件 |
|------|------|
| 5174 | dialogue_app（对话演示） |
| 5175 | gacha_app（抽卡验证） |
| 5176 | bag_app（背包系统） |
| 5177 | map_app（地图编辑） |
| 5178+ | ← 新组件从这里开始 |

**实现时对应的技术规范**：

| 要做的事 | 看哪篇 |
|----------|--------|
| 搭目录、起项目 | `01_项目结构规范` / `08_开发流程指南` |
| 技术栈 / 依赖 | `02` / `03` |
| 跟主程序通信、同步数据 | `04_IPC通信API规范` |
| 对接表格字段 | `05_字段映射规范` |
| 界面风格（Cyberpunk） | `07_UI组件规范` |
| 组件名多语言 | `11_多语言支持规范` |

## 附 · 填好的示例（供参考）

> 下面是按本模板填的一个虚构小组件，照着体会怎么填。

**第 1 部分**：组件中文名 = 称号系统；一句话作用 = 把称号表变成可翻看的称号墙，策划点一下就能看每个称号的解锁条件；类型 = 预览型。

**第 2 部分**：工作表名 = 称号表；第 4 行起是数据；id=A，称号名=B，图标=C，解锁条件描述=D。

**第 3 部分**：顶栏标题「称号墙」+ 返回按钮；主体是卡片网格，每张卡显示图标 + 称号名；点卡片右侧弹出解锁条件；按钮「同步数据」「设置映射」。

**第 4 部分**：zh-CN 称号系统 / en-US Title System / ja-JP 称号システム / ko-KR 칭호 시스템。

**第 5 部分特有项**：称号表 30 个称号 → 墙上 30 张卡，名称图标都对；点任一卡，右侧显示该称号 D 列的解锁条件文字。

**第 6 部分**：name=`title_app`，toolType=`title`，componentType=`preview`，icon=`award`，devPort=`5178`。
