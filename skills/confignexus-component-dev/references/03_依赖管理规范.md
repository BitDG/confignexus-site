# 03 依赖管理规范

> 本文档定义了 ConfigNexus 组件的依赖管理策略，实现依赖共享和一致性。

---

## 🎯 核心原则

**所有组件统一使用 `app/node_modules` 目录的依赖**

这样做的好处：
- ✅ 避免重复安装相同依赖
- ✅ 确保所有组件使用相同版本
- ✅ 减少磁盘空间占用
- ✅ 简化依赖更新流程

---

```
    └── ...
```

## 📝 组件 `package.json` 模板

组件的 `package.json` 只需声明脚本，**不声明依赖**：

```json
{
    "name": "component_name",
    "private": true,
    "version": "0.0.1",
    "description": "组件描述",
    "type": "module",
    "scripts": {
        "dev": "vite",
        "build": "vite build",
        "preview": "vite preview"
    },
    "dependencies": {},
    "devDependencies": {}
}
```

## 🔧 工作原理

### Node.js 模块解析机制

Node.js 按以下顺序查找模块：

1. 当前目录的 `node_modules/`
2. 父目录的 `node_modules/`
3. 继续向上查找直到根目录

因此，当组件（如 `dialogue_app`）运行 `npm run dev` 时：
1. 在 `app/dialogue_app/node_modules/` 中找不到依赖（目录为空或不存在）
2. 向上查找 `app/node_modules/`
3. 找到所需依赖 ✅

### Vite 模块解析

Vite 同样遵循 Node.js 的模块解析规则，会自动向上查找 `node_modules`。

## 📥 安装依赖

### 首次安装

```powershell
# 在 app 目录下运行
cd path/to/app
npm install
```

### 添加新依赖

```powershell
# 在 app 目录下运行
cd path/to/app
npm install <package-name>
```

### 更新依赖

```powershell
# 在 app 目录下运行
cd path/to/app
npm update
```

---

## ⚠️ 注意事项

### 1. 不要在组件目录运行 `npm install`

```powershell
# ❌ 错误做法
cd app/dialogue_app
npm install    # 这会在组件目录创建 node_modules，破坏共享机制
```

### 2. 组件目录的 `node_modules` 应被忽略

如果组件目录意外创建了 `node_modules`，应将其删除：

```powershell
# 删除组件目录下的 node_modules（如果存在）
Remove-Item -Recurse -Force app/dialogue_app/node_modules
```

### 3. 符号链接（可选优化）

如果需要显式声明依赖关系，可以创建符号链接：

```powershell
# 在组件目录创建指向共享 node_modules 的符号链接
cd app/dialogue_app
mklink /D node_modules ..\node_modules
```

但这通常不是必需的，因为 Node.js 的模块解析机制已经能自动处理。

## 📋 依赖版本管理

### 当前统一版本

| 依赖 | 版本 | 说明 |
|------|------|------|
| react | ^18.3.1 | UI 框架 |
| react-dom | ^18.3.1 | React DOM |
| vite | ^6.0.3 | 构建工具 |
| tailwindcss | ^4.0.0 | CSS 框架 |
| @tailwindcss/vite | ^4.0.0 | Vite 插件 |
| @tailwindcss/postcss | ^4.0.0 | PostCSS 插件 |
| @vitejs/plugin-react | ^4.3.4 | React Vite 插件 |
| typescript | ^5.7.2 | 类型系统 |
| lucide-react | ^0.468.0 | 图标库 |

### 版本锁定

使用 `package-lock.json` 锁定确切版本：

```powershell
# 在 app 目录
npm ci  # 使用 package-lock.json 安装确切版本
```
