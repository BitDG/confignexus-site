# 09 代码组织规范

> 本文档定义了 ConfigNexus 组件的代码组织最佳实践，确保代码可维护性和一致性。

---

## 📏 文件大小规范

| 类型 | 最大行数 | 说明 |
|------|----------|------|
| **组件文件** | 300 行 | 单个 React 组件 |
| **主入口文件** | 500 行 | App.tsx / index.tsx |
| **类型定义** | 200 行 | types.ts |
| **工具函数** | 200 行 | utils/*.ts |

> ⚠️ 超过限制时，应考虑拆分文件。

---

## 📁 目录结构规范

### 标准组件目录结构

```
app/[component_name]/
├── components/           # UI 组件
│   ├── TopBar.tsx
│   ├── Sidebar.tsx
│   ├── ItemCard.tsx
│   └── modals/          # 弹窗组件 (可选)
│       ├── SettingsModal.tsx
│       └── MappingModal.tsx
├── hooks/               # 自定义 Hooks (可选)
│   └── useDataSync.ts
├── utils/               # 工具函数 (可选)
│   └── dataParser.ts
├── types.ts             # 类型定义
├── constants.ts         # 常量定义
├── App.tsx              # 主应用组件
├── index.tsx            # 入口文件
├── index.css            # 样式文件
└── ...                  # 配置文件
```

## 🧩 组件拆分规范

### 何时拆分组件

1. **逻辑独立** - 组件有独立的状态或功能
2. **可复用** - 在多处使用相同 UI
3. **代码过长** - 超过 300 行
4. **便于维护** - 降低单文件复杂度

### 组件分类

| 分类 | 目录 | 示例 |
|------|------|------|
| **布局组件** | `components/` | `TopBar`, `Sidebar` |
| **展示组件** | `components/` | `ItemCard`, `ListItem` |
| **弹窗组件** | `components/` 或 `components/modals/` | `SettingsModal`, `MappingModal` |
| **业务组件** | `components/` | `MailList`, `MissionPanel` |

## 📝 类型定义规范

### types.ts 结构

```typescript
// ============================================
// 基础类型
// ============================================

export enum Rarity {
  COMMON = 'COMMON',
  RARE = 'RARE',
  EPIC = 'EPIC',
  LEGENDARY = 'LEGENDARY'
}

// ============================================
// 数据接口
// ============================================

export interface Item {
  id: string;
  name: string;
  rarity: Rarity;
  quantity: number;
}

// ============================================
// 字段映射
// ============================================

export interface FieldMapping {
  sheetName: string;
  startRow: number;
  columns: {
    id: string;
    name: string;
    // ...
  };
}

// ============================================
// 工具函数
// ============================================

export function colToIndex(col: string): number {
  let index = 0;
  for (let i = 0; i < col.length; i++) {
    index = index * 26 + (col.charCodeAt(i) - 64);
  }
  return index - 1;
}

// ============================================
// 常量
// ============================================

export const STORAGE_KEY_MAPPING = 'component_field_mapping';

export const DEFAULT_MAPPING: FieldMapping = {
  sheetName: '',
  startRow: 4,
  columns: { id: '', name: '' }
};
```

## 🪝 自定义 Hooks 规范

### hooks/ 目录使用场景

- 数据同步逻辑 (`useDataSync`)
- 本地存储管理 (`useLocalStorage`)
- 窗口尺寸监听 (`useWindowSize`)

### 命名规范

- 以 `use` 开头
- 驼峰命名法
- 描述功能

```typescript
// hooks/useDataSync.ts
export function useDataSync(mapping: FieldMapping) {
  const [data, setData] = useState<Item[]>([]);
  
  useEffect(() => {
    // 监听数据同步事件
  }, [mapping]);
  
  return { data, setData };
}
```

## ✅ 代码组织检查清单

创建或修改组件时，确认以下事项：

- [ ] 单文件不超过 500 行
- [ ] 类型定义放在 `types.ts`
- [ ] UI 组件放在 `components/` 目录
- [ ] 复杂工具函数放在 `utils/` 目录
- [ ] 自定义 Hooks 放在 `hooks/` 目录
- [ ] 常量定义放在 `constants.ts`
- [ ] 入口文件 (`index.tsx`) 仅包含渲染逻辑
- [ ] 主组件 (`App.tsx`) 负责状态管理和布局
