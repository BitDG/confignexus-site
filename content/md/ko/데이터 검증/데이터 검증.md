# 데이터 검증

구성 테이블 데이터의 정확성과 완전성을 보장합니다. 기본 형식 검증과 DSL 규칙 검증 2단계 체크 메커니즘을 지원합니다.

## 검증 유형 개요

### 기본 검증 (자동)

| 유형 | 설명 | 예시 |
|------|------|------|
| ID 고유성 | A열의 ID가 중복되지 않아야 함 | A5=1, A6=1 → 오류 |
| 딕셔너리 형식 | `List<Dictionary>` 는 `[{key:value}]` 형식 | `[{1:100}]` ✓, `{1:100}` ✗ |
| 배열 형식 | `int[]`/`float[]`/`string[]` 는 `[x,y]` 형식 | `[1,2,3]` ✓, `1,2,3` ✗ |

### DSL 규칙 검증 (검증 행에서 설정)

테이블 구조의 **검증 행**에 DSL 규칙을 작성하면 시스템이 자동으로 검사합니다:

| 규칙 | 구문 | 예시 |
|------|------|------|
| 필수 | `required` | 필드를 비울 수 없음 |
| 숫자 범위 | `range(min,max)` | `range(0,100)` — 0~100 사이 |
| 열거형 | `enum(a,b,c)` | `enum(warrior,mage,archer)` — 이 값만 허용 |
| 문자열 길이 | `len(min,max)` | `len(1,50)` — 길이 1~50 |
| 정규식 | `regex(pattern)` | `regex(^[A-Z]{3}_\d+$)` — 패턴 매칭 |
| 고유성 | `unique` | 열 값이 중복되지 않아야 함 |
| 테이블 간 참조 | `ref(테이블@열)` | `ref(ItemConfig@id)` — 다른 테이블에 존재해야 함 |
| 열거 참조 | `enum_ref(테이블@열)` | `enum_ref(TypeConfig@type)` — 다른 테이블에서 열거형 가져오기 |

#### 규칙 조합

여러 규칙은 `&&`로 연결하며, 모두 통과해야 합격:

```
required&&range(1,999)          → 필수이며 1~999 사이
required&&len(1,20)&&regex(^[a-z_]+$)  → 필수, 길이 1~20, 소문자+밑줄만
```

#### 리스트 요소 검증

열 타입이 `list<int>`, `list<string>` 등인 경우, 규칙이 **각 요소**에 자동 적용됩니다:

```
열 타입: list<int>    규칙: range(1,100)
값: [1,50,200]  → 요소 [2]: 값 200이 범위 [1, 100] 밖
```

## 사용 방법

메뉴 바에서 "데이터 검증" 버튼을 클릭합니다. 결과는 로그 뷰어의 검증 탭에 표시됩니다.

## 검증 영역

각 워크시트의 검증 영역은 테이블 구조에 기반합니다:
- **시작 열**: A열
- **시작 행**: 데이터 시작 행 (테이블 구조 정의에 따라, 기본값 5행)
- **종료**: 유효 데이터의 마지막 행과 마지막 열까지
- **ID 종료**: A열이 빈 셀을 만나면 검증 중단

## 워크플로우 데모

### 단계 1: 테이블 구조 설정

올바른 행 구조를 확인합니다. 기본 5행 헤더:

| 행 | 역할 | 예시 |
|----|------|------|
| 1행 | 필드명 | id, name, type, price |
| 2행 | 표시명 | ID, 이름, 유형, 가격 |
| 3행 | 데이터 타입 | int, string, int, float |
| 4행 | 설명 | 고유 ID, 아이템 이름, 카테고리, 구매 가격 |
| 5행 | 검증 규칙 | required, required&&len(1,50), enum(1,2,3), range(0,9999) |
| 6행~ | 데이터 | 1, 철검, 1, 100.5 |

### 단계 2: 검증 규칙 작성

검증 행에 DSL 규칙을 입력합니다:

```
A열 (id):     required
B열 (name):   required&&len(1,50)
C열 (type):   required&&enum(1,2,3)
D열 (price):  range(0,9999)
E열 (ref_id): ref(ItemConfig@id)
```

### 단계 3: 검증 실행

video:Res/zh/videos/数据验证.webm|데이터 검증

"데이터 검증" 버튼을 클릭하면 시스템이 다음을 수행합니다:
1. 모든 워크시트를 순회
2. 각 시트의 검증 행 규칙 읽기
3. 각 데이터 셀에 대해 해당 규칙 실행
4. 오류를 로그 뷰어에 출력

### 단계 4: 확인 및 수정

로그 패널의 "검증" 탭에 결과가 표시됩니다:
- 오류 항목을 클릭하면 해당 셀로 이동
- 오류 수준: 구체적인 규칙 실패 이유 표시
- 수정 제안: 각 오류에 해결 방안 포함

## 테이블 간 참조 검증

`ref()`와 `enum_ref()`는 워크시트 간 검증을 지원합니다:

```
시나리오: 아이템 테이블의 type 필드가 타입 설정 테이블을 참조

아이템 테이블 검증 행 C열:  ref(TypeConfig@id)
  → "TypeConfig"라는 이름의 워크시트를 찾음
  → 해당 "id" 열의 모든 값을 읽음
  → 현재 열의 각 값이 해당 집합에 존재하는지 검증
```

## 커스텀 규칙 확장

DSL 규칙 외에도 코드로 커스텀 검증 함수를 등록할 수 있습니다:

```javascript
window.validator.config.customRules = [
  {
    validate: (value, cellConfig) => {
      if (cellConfig.type === 'int' && value % 2 !== 0) {
        return '이 열에는 짝수만 허용됩니다';
      }
      return true;
    }
  }
];
```
