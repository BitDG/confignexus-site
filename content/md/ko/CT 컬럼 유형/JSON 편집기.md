# JSON 편집기

보상 설정을 셀에 넣으면 이렇게 생겼습니다: `{"items":[{"id":1001,"rate":0.5}],"gold":50}` — 셀이 너무 좁아 다 보이지 않고, 괄호를 직접 고치다 따옴표 하나만 빠져도 프로그램이 바로 죽으며, 여러 겹 중첩이면 어느 층을 고쳐야 할지도 모릅니다. JSON 편집기가 바로 이것을 해결합니다: 특정 열을 JSON 타입으로 설정하면, 셀을 더블 클릭할 때 Monaco 코드 뷰 + 트리 뷰의 듀얼 뷰가 떠서, 왼쪽에서 코드를 고치면 오른쪽 트리가 즉시 동기화되고, 오른쪽에서 노드를 클릭하면 왼쪽 커서가 따라가며, 형식이 틀리면 저장 버튼이 비활성화되어 잘못된 JSON은 셀에 들어가지 못합니다.

> [!tip]
> JSON(JavaScript Object Notation, 경량 데이터 교환 형식)은 중첩 구조 저장에 적합합니다 — 보상 목록, 아이템 속성, 레벨 파라미터. 단순한 "객체 배열, 각 항목 구조가 고정"이라면 **다중 데이터 편집**이 더 직관적입니다([[다중 데이터 편집 모드]] 참고).

## 사용 방법

### 1단계: 특정 열을 JSON 편집기로 설정

대상 열의 임의의 셀을 선택 → **우클릭** → **CT 속성 → JSON 편집기로 설정**. 한 번에 열 전체에 적용됩니다.

> [!note]
> CT 속성(Column Type, 열 타입)은 "이 열에 어떤 데이터가 들어가는지"를 지정하는 라벨로, 한 번 설정하면 열 전체에 적용됩니다. 데모 프로젝트의 `drops` 열(D 열)이 JSON 편집기를 연결하는 용도이며, D 열의 임의 셀을 우클릭하면 설정할 수 있습니다.

### 2단계: 데이터 셀을 더블 클릭해 편집기 열기

JSON 열에서 **데이터 행의 셀을 더블 클릭**하면 Monaco + 트리 뷰 팝업이 나타납니다.

> [!warning]
> **데이터 행**만 더블 클릭하면 뜹니다. 헤더 영역(필드명/타입/검증 규칙 행)을 더블 클릭하면 뜨지 않습니다 — 리치 텍스트 편집기와 마찬가지로 의도된 것으로, 헤더를 데이터로 착각해 수정하는 것을 막습니다.

### 3단계: 듀얼 뷰에서 편집

왼쪽은 Monaco 코드 뷰(VS Code와 동일한 편집기)로 JSON 텍스트를 직접 수정하고, 오른쪽 트리 뷰가 자동으로 동기화되어 층층이 펼쳐지며, 노드를 클릭하면 커서가 해당 행으로 점프합니다.

![JSON 편집기 듀얼 뷰](Res/zh/images/JSON编辑器双视图.png)

자주 쓰는 트리 뷰 작업:

| 작업 | 효과 |
|------|------|
| 노드 클릭 | 왼쪽 편집기 커서가 해당 행으로 이동 |
| 노드 더블 클릭 | 작은 창에서 이 값만 단독 편집(숫자/문자열/불리언에 맞는 컨트롤) |
| 노드 우클릭 | 자식 노드 추가 / 삭제 / **경로 복사** / 모두 접기 |
| 노드 드래그 | 배열 요소 순서 조정 |

### 4단계: 형식 확인, 저장

하단 상태 바가 JSON이 유효한지 실시간으로 표시합니다 — 유효하면 노드 수와 최대 깊이를, 오류가 있으면 오류 행 + 설명을 표시합니다. **형식이 틀리면 저장 버튼이 비활성화**되어, 수정해야만 셀에 쓸 수 있습니다.

> [!tip]
> 흔한 작은 오류(끝쉼표 `[1,2,]`, 작은따옴표 `{'key':'val'}`)는 편집기가 열기 전에 **먼저 자동 복구를 시도**합니다. 자동 복구가 안 되는 경우에만 오류를 알리고 문제 행으로 위치를 잡아 줍니다. 데모 프로젝트의 7번째 행(엘리트 고블린)에는 끝쉼표가 미리 들어 있어 열면 자동 복구 효과를 볼 수 있고, 8번째 행(스켈레톤 병사)은 불완전한 JSON이라 오류 위치 표시를 볼 수 있습니다.

## 값 타입 색상 표시

트리 뷰에서 각 값은 타입별로 색상이 구분됩니다:

| 타입 | 색상 | 예시 |
|------|------|------|
| 문자열 | 보라 | `"장비 드롭"` |
| 숫자 | 파랑 | `100` |
| 불리언 | 주황 | `true` |
| null | 회색 | `null` |
| 배열 | 초록 | `[3]`(3개 요소) |
| 객체 | 초록 | `{2}`(2개 필드) |

타입은 양방향 동기화 시 의도치 않게 바뀌지 않습니다 — 코드 영역을 직접 수정하지 않는 한.

## JSON 편집기 vs 다중 데이터 편집

| 상황 | 어느 것을 쓸까 |
|------|----------------|
| 셀에 하나의 JSON 객체 / 임의 중첩 구조 | JSON 편집기 |
| 셀이 객체 배열이며 각 항목 구조가 고정(예: 보상 목록) | 다중 데이터 편집(스키마 기반, 열 정렬이 더 직관적) |
| 임시 탐색 / 구조 불확실 | JSON 편집기(더 유연) |

## 주의 사항

> [!tip]
> 트리 노드 우클릭 → **경로 복사**로 `rewards[0].count` 같은 JSONPath를 얻을 수 있고, Python 수식 `=json_get('rewards[0].count')`에 바로 써서 값을 자동으로 읽을 수 있습니다.

> [!warning]
> 셀에 수 MB의 큰 JSON을 넣으면 편집기 로딩이 느려질 수 있습니다 — 이런 큰 구조는 외부 `.json` 파일에 두고 **외부 참조 소스**로 연결하는 편이 더 적합합니다([[외부 참조 소스]] 참고).

> [!note]
> "이 열은 JSON 편집기 열"이라는 설정(CT 속성)은 열의 메타데이터로 `.cnx`에 저장되며, 필드로 내보내지지 않습니다. `.cnx`로 저장하면 열 타입이 유지되지만 `.xlsx`로 저장하면 사라집니다. [[cnx 프로젝트 파일]] 참고.
