# 🚀 첫 수업

ConfigNexus를 처음 열고 수많은 버튼 앞에서 어디서부터 시작할지 막막한가요? 이 글은 **첫 번째 설정 테이블을 처음부터 끝까지 완성하는 과정**을 안내합니다 — 소프트웨어를 여는 것부터, 데이터를 게임 엔진이 바로 읽을 수 있는 형식으로 내보내는 것까지. 전 과정에서 코드를 쓸 필요 없이 따라 클릭하기만 하면 됩니다.

> [!tip]
> 이 글은 「전체 로드맵」입니다. 각 단계에서 언급하는 기능에는 전용 상세 튜토리얼이 있으니, 더 깊이 알고 싶다면 왼쪽 목차에서 해당 페이지를 찾으세요(본문에서는 링크로 표시).

---

## 무엇을 하는 기능인가

한마디로: **ConfigNexus는 게임 설정 데이터를 위한 "슈퍼 Excel"**입니다. Excel처럼 표를 채우고(수치, 텍스트, 아이템, 대화……), 소프트웨어가 데이터에 오류가 없는지 검증해 주며, 마지막에 Unity / Unreal / Godot / 자체 엔진이 바로 읽을 수 있는 형식(JSON, C#, Lua 등)으로 한 번에 내보냅니다.

기획자가 표를 채우고, 프로그래머가 데이터를 읽고, 아티스트가 리소스를 연결합니다. 세 직군이 하나의 프로젝트를 공유하며 더 이상 "Excel 주고받기"에 의존하지 않습니다.

---

## 1단계: 인터페이스 익히기

열면 Excel과 비슷한 메인 창이 나타납니다. 먼저 네 곳을 알아 두세요:

| 위치 | 무엇인가 |
|------|----------|
| 상단 메뉴 바 | **파일 / 보기 / 도구 / 도움말** 네 개 메뉴, 모든 기능 진입점이 여기 있음 |
| 테이블 영역 | 가운데의 큰 테이블, Excel과 동일하게 조작(값 입력, 필터, 고정, 수식) |
| 탭 바 | 테이블 위쪽, 여러 테이블을 동시에 열어도 서로 영향 없음([[멀티 탭 관리]] 참고) |
| 우측 하단 데스크톱 펫 | 움직이는 작은 도우미, 클릭하면 AI 대화와 자주 쓰는 도구가 펼쳐짐 |

> [!note]
> 상단 메뉴의 소속만 기억하세요: **새로 만들기/열기/가져오기/내보내기/저장**은 「파일」에; **로그/파일 브라우저**는 「보기」에; **Python 스크립트/스크립트 라이브러리**는 「도구」에; **튜토리얼/정보**는 「도움말」에 있습니다.

---

## 2단계: 첫 번째 테이블 만들기

네 가지 시작 방법이 있으니 하나를 고르세요:

1. **처음부터 새로 만들기**: 메뉴 **파일 → 새 프로젝트**(또는 탭 바의 ➕)로 빈 테이블을 얻어 직접 채웁니다.
2. **기존 Excel 가져오기**: 메뉴 **파일 → Excel 가져오기**로 가지고 있는 `.xlsx` / `.xls`를 선택하면 데이터가 그대로 들어옵니다([[Xlsx 파일]] 참고).
3. **JSON / CSV 가져오기**: 메뉴 **파일 → JSON 가져오기** 또는 **CSV 가져오기**([[JSON 파일]] [[CSV 파일]] 참고).
4. **템플릿 적용**: 메뉴 **파일 → 템플릿**에서 시작 템플릿을 골라 바로 수정합니다.

> [!tip]
> 초보자는 먼저 「Excel 가져오기」로 기존 테이블을 옮겨 오는 것이 가장 체감하기 좋습니다.

---

## 3단계: 데이터 편집

테이블에 들어가면 Excel처럼 바로 채우면 됩니다. ConfigNexus가 Excel보다 더 가진 것은 **CT 열 타입** — 특정 열에 "이 열에 어떤 데이터가 들어가는지"를 지정하면 편집 경험이 즉시 향상됩니다:

- **열 머리글 우클릭 → 열 타입 설정**, 선택 가능:
  - **날짜**: 더블 클릭하면 날짜 선택기가 떠서 수동 입력 불필요([[날짜 편집기]] 참고)
  - **리소스**: 더블 클릭해 이미지/오디오를 선택하면 셀에 썸네일 표시([[리소스 편집기]] 참고)
  - **JSON**: 복잡한 중첩 구조를 코드+트리 뷰로 편집, 셀에서 손으로 짜지 않음([[JSON 편집기]] 참고)
  - **다중 데이터**: `[{...},{...}]` 같은 객체 배열을 시각적으로 일괄 편집([[다중 데이터 편집 모드]] 참고)
  - **리치 텍스트**: Notion처럼 보이는 그대로 편집([[리치 텍스트 편집]] 참고)

> [!tip]
> 처음부터 서둘러 CT를 설정할 필요는 없습니다. 일반 텍스트/숫자는 바로 채우면 됩니다. "날짜 형식을 자꾸 틀린다" "이미지 경로가 기억나지 않는다" 같은 불편을 만나면, 그때 해당 열에 알맞은 CT 타입을 설정하세요.

---

## 4단계: 데이터에 오류가 없는지 확인

표를 다 채웠으면 내보내기 전에 한 번 점검해, 잘못된 데이터를 게임에 들이지 마세요.

ConfigNexus는 **검증 규칙 DSL**을 사용합니다: 헤더 행에 작은 규칙(예: 어떤 열에 `required`(필수), `unique`(중복 불가), `range(1,100)`(값이 1~100 사이))을 쓰면, 소프트웨어가 **잘못 채운 셀을 실시간으로 빨갛게 표시**하고, 검증 로그를 클릭하면 오류 셀로 바로 이동합니다.

- 자세한 작성법은 [[데이터 검증]]과 [[검증 규칙 DSL]] 두 편을 보세요.
- 초보자가 기억할 가장 유용한 것: "ID 열"에 `unique`를 추가하면 중복 ID를 즉시 찾아냅니다.

---

## 5단계: 엔진으로 내보내기

데이터에 문제가 없으면 한 번에 내보냅니다:

1. 메뉴 **파일 → 데이터 내보내기**로 내보내기 패널을 엽니다.
2. 엔진이 필요로 하는 형식을 체크(복수 선택 가능) — 총 **10가지**:
   - 텍스트류: **JSON / YAML / CSV**
   - 코드류(로더 내장): **C# / TypeScript / Lua / C++**
   - 바이너리류: **Bytes / MessagePack / Protobuf**
3. 각 형식마다 출력 폴더를 선택하고 내보내기를 클릭합니다.
4. 「내보내기 전 검증」을 체크해 두면 오류가 있을 때 막아 줍니다.

> [!tip]
> 무엇을 고를지 모르겠다면? Unity는 **C# + JSON**, Unreal은 **C++ + JSON**, 프런트엔드/소규모 게임은 **TypeScript** 또는 **JSON**을 고르세요. [[데이터 내보내기]] 참고.

---

## 6단계: 프로젝트 저장

작업을 저장하는 것을 잊지 마세요:

- 메뉴 **파일 → 프로젝트 저장**, 또는 단축키 `Ctrl+S`.
- **`.cnx`** 형식(ConfigNexus 네이티브 프로젝트 파일)으로 저장하는 것을 권장합니다 — CT 열 타입, 테이블 간 참조, Python 수식 등 Excel이 담지 못하는 것을 **완전히 보존**하므로, 닫았다 다시 열어도 그대로 남아 있습니다.

> [!warning]
> `.xlsx`로 저장하면 CT 타입, 테이블 간 참조, 수식 같은 고급 정보가 사라집니다. 일상 작업은 `.cnx`로 저장하고, 남에게 넘기거나 보관할 때만 해당 형식으로 내보내세요.
