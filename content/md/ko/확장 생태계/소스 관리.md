# 소스 관리(Git / SVN)

기획자가 어떤 아이템 수치를 바꿨는데, 오후에 프로그래머가 와서 "어디 몇 줄을 바꿨어?"라고 물으면 기억이나 스크린샷 대조에 의존할 수밖에 없습니다 — 이런 비효율적 협업은 모든 팀이 겪습니다. 설정 테이블을 Git / SVN에 포함하는 것은 코드에 버전 이력을 주는 것과 같습니다: 누가 언제 어느 셀을 바꿨고, 바꾸기 전후가 각각 무엇인지 로그 한 줄로 전부 보이니, 더 이상 기억에 의존하지 않습니다.

ConfigNexus에는 Git / SVN 클라이언트 패널이 내장되어 있습니다 — 설정 테이블도 코드이며, 버전 관리에 포함하면 "누가 어느 값을 바꿨는가"를 명확히 조회할 수 있습니다. 패널은 파일 브라우저의 왼쪽 사이드바에 붙습니다.

## 기능 개요

| 기능 | Git | SVN |
|------|-----|-----|
| 변경 목록 | ✅ 스테이징됨 / 스테이징 안 됨 / 추적 안 됨 세 칸 | ✅ 단일 변경 칸(SVN은 staging 개념 없음) |
| 커밋 | ✅ | ✅ |
| 풀 / 업데이트 | ✅ pull | ✅ update |
| 푸시 | ✅ push | — (SVN commit은 서버로 바로) |
| 되돌리기 | ✅ discard / revert | ✅ revert |
| 브랜치 관리 | ✅ branches / checkout / create / delete / merge | — |
| 임시 저장 | ✅ stash / stash pop | — |
| 이력 보기 | ✅ log + diff | ✅ log + diff |
| 파일 배지 | ✅ M / A / D / U / C | ✅ M / A / D / ? / C |

## 전제 조건

- **Git**: 시스템 PATH에 `git` 명령(Windows용 Git을 설치하면 기본으로 설치됨)
- **SVN**: 시스템 PATH에 `svn.exe`(TortoiseSVN 설치 시 **command line client tools** 옵션을 체크해야 설치됨)

> [!NOTE]
> 설치하지 않아도 괜찮습니다 — ConfigNexus는 시작 시 자체 점검해, 설치되지 않은 플러그인의 아이콘을 자동으로 숨기며 다른 기능에 영향을 주지 않습니다.

## 패널 열기

파일 브라우저 왼쪽 세로 아이콘 바:

- 🌿 → Git 소스 관리 패널
- 🌐 → SVN 소스 관리 패널

## 배지 시스템

파일 브라우저의 파일명 옆에 버전 관리 상태가 자동으로 표시됩니다:

| 배지 | 의미 |
|------|------|
| M | 수정됨 |
| A | 추가됨 |
| D | 삭제됨 |
| U / ? | 추적 안 됨 |
| C | 충돌 |

배지는 30초 캐시됩니다. commit / 되돌리기 동작을 하면 배지가 즉시 새로 고쳐집니다.

## Git 패널 작업

### 커밋 흐름

1. **스테이징 안 됨** 영역에 나열된 이번 변경을 확인
2. 파일명을 단일 클릭해 diff 보기
3. 파일명 오른쪽 **+**를 클릭해 스테이징(스테이징됨 영역으로 이동)
4. 하단 입력창에 commit message 작성
5. **커밋** 클릭 → 완료

### 브랜치 관리

패널 상단 브랜치명 옆 🌿 chip → 브랜치 popover 표시:

- 모든 로컬 / 원격 브랜치 나열
- 현재 브랜치 앞에 ⭐
- 다른 브랜치 클릭 → 전환(커밋 안 된 변경이 있으면 먼저 안내)
- **+ 새 브랜치** 이름 입력 → 새 브랜치로 자동 checkout

### 임시 저장(stash)

커밋하고 싶지 않지만 브랜치를 바꿔야 할 때:

1. 패널 툴바에서 **현재 변경 임시 저장** 메모 입력 → stash 스택에 push
2. 다른 브랜치로 전환해 작업
3. 원래 브랜치로 복귀 → 툴바에서 **최근 임시 저장 꺼내기** → 변경 복원

## SVN 패널 작업

### 커밋 흐름

1. 변경 목록에서 커밋할 파일 체크
2. 하단에 commit message 입력
3. **커밋** 클릭 → SVN 서버로 바로 전송(SVN은 로컬 staging 개념 없음)

### 서버 최신 동기화

툴바 **⬇ 업데이트** → 서버 최신 버전을 로컬로 가져옴.

## 성능 최적화

v0.0.3부터 Git / SVN 배지와 변경 목록은 "저장소 전체 스냅샷 캐시 + 요청 병합"을 사용합니다:

- 처음 열 때 한 번 `git status` / `svn status` 조회
- 30초 내 모든 파일의 배지 조회는 캐시를 거침
- commit / pull / 되돌리기 등을 하면 캐시 자동 무효화

효과: 파일 수백 개가 있는 디렉터리에서 파일 브라우저를 열어도 **더 이상 끊기지 않습니다**.

## scope 한정

소스 관리 패널은 기본적으로 **저장소 전체**의 변경을 나열합니다. **현재 파일 브라우저 위치** 아래의 변경만 나열하게 할 수도 있습니다:

- 패널 상단 **현재 범위** chip으로 "저장소 전체 / 현재 디렉터리" 전환
- 설정 테이블 프로젝트가 크고 변경 파일이 많을 때는 "현재 디렉터리"로 전환하기를 강력히 권장

## 대량 변경 목록(10000+ 파일)

만 단위 변경 시 패널이 자동으로 페이지를 나눕니다:

- 각 그룹은 상위 200개만 표시
- 하단에 **더 불러오기 (+200)** / **전체 표시** 버튼
- 10000개 DOM 노드를 한 번에 넣어 브라우저를 멈추게 하지 않음

## 테이블 diff 통합

**테이블 비교 DLC**를 설치했다면:

- 변경 목록의 `.xlsx` / `.cnx` 파일을 클릭 → "테이블 diff인가 텍스트 diff인가" 팝업
- 테이블 diff: HEAD 버전과 작업 영역 버전 비교, 셀 단위 highlight
- 텍스트 diff: 일반 unified diff

[[테이블 비교]] 튜토리얼 참고.

## 주의 사항

> [!WARNING]
> 변경 되돌리기는 **복구할 수 없습니다** — `git checkout --`와 `svn revert`는 모두 파일을 마지막 커밋 상태로 되돌리며, 저장하지 않은 작업은 바로 사라집니다. 시스템이 먼저 확인 대화상자를 띄우지만, 클릭하기 전에 정말 이 변경이 필요 없는지 확인하세요.

> [!TIP]
> Git 이력에서 어떤 commit을 펼치면 → 이 commit이 어느 파일을 바꿨는지 + 각 파일의 diff를 봅니다. 작업 영역과 비교하려면 **HEAD 비교** 도구를 쓰세요(테이블 비교 편에서 설명).
