# cnx 프로젝트 파일

매일 xlsx로 프로젝트를 저장했더니, 열 때마다 CT 열 타입을 다시 설정해야 하고, 검증 규칙은 사라지고, 지난번에 쓴 Python 수식은 찾을 수 없다 — 이는 xlsx가 애초에 이런 설정을 담지 못하기 때문입니다. `.cnx`는 ConfigNexus의 **네이티브 프로젝트 파일**입니다: 테이블 데이터, CT 타입, 검증 규칙, 테이블 간 참조, Python 수식을 하나의 파일에 모두 담아 **닫았다 다시 열어도 전부 남아 있습니다**.

아래 버튼을 눌러 데모 프로젝트를 가져와 .cnx가 어떻게 열리는지 바로 확인하세요:

createtab:Res/zh/templates/富文本编辑演示.cnx

## .xlsx와의 차이

| 항목 | .xlsx | .cnx |
|------|-------|------|
| 파일 크기 | 동일 데이터 기준 더 작음 | 더 큼(메타데이터 포함) |
| 수식 | ✅ Excel 수식 | ✅ Excel 수식 + Python 수식 |
| 스타일 | ✅ | ✅ |
| 셀 병합 | ✅ | ✅ |
| CT 열 타입 | ❌ 가져올 때 사라짐 | ✅ 완전 보존 |
| 테이블 간 참조 | ❌ | ✅ |
| 외부 참조 소스 설정 | ❌ | ✅ |
| 리치 텍스트 / JSON 뷰 상태 | ❌ | ✅ |
| 검증 규칙 DSL | ❌ 내보낼 때 일반 텍스트로 퇴화 | ✅ |
| Excel 호환 열기 | ✅ | ❌ |

**요약**: 장기 프로젝트는 `.cnx`로, 외부 협업이나 최종 납품은 `.xlsx`로.

## 언제 cnx를 쓰는가

- ✅ 일상 프로젝트 파일(당신과 팀 동료가 ConfigNexus에서 수정하는 것)
- ✅ Git에 커밋해 버전 관리하는 소스 파일
- ✅ CT 열 / 검증 규칙 / Python 수식을 보존해야 하는 경우

## 언제 cnx를 쓰지 않는가

- ❌ 프로그래머에게 보여줄 때(그들은 못 열며, 먼저 json/xlsx로 내보내야 함)
- ❌ ConfigNexus 비사용자에게 보여줄 때
- ❌ 이메일 / 메신저로 임시 공유(xlsx가 더 범용적)

## 새 cnx 프로젝트 만들기

메인 창 메뉴 → **파일 → 새 cnx 프로젝트** → 저장 위치 선택 → 기본 시트 하나를 포함한 빈 `.cnx`가 자동 생성됩니다.

## xlsx를 cnx로 변환

메인 창에서 xlsx 열기 → 메인 창 메뉴 → **파일 → cnx로 다른 이름으로 저장** → 저장 위치 선택.

변환 후:

- 모든 데이터 보존
- 일반 수식 보존
- 스타일 보존
- CT 열 타입은 **다시 연결해야 함**(xlsx에는 이 정보가 없음)
- 검증 규칙은 **다시 작성해야 함**

## cnx를 xlsx로(내보내기)

메인 창 메뉴 → **파일 → 내보내기 → xlsx** → 출력 경로 선택.

퇴화하는 것:

- CT 열 타입 → 일반 문자열 열로 퇴화
- Python 수식 → **내보내지지 않음**(xlsx에는 Python 실행 환경이 없음)
- 검증 규칙 DSL → xlsx의 "데이터 유효성 검사"로 변환(일부 규칙만 변환되고 복잡한 규칙은 사라짐)

## 더블 클릭 연결

ConfigNexus는 `.cnx`의 더블 클릭 연결을 등록합니다 — 파일 관리자에서 `.cnx` 파일을 더블 클릭하면 ConfigNexus로 바로 열립니다.

## 파일 내부 구조

`.cnx`는 본질적으로 zip입니다:

```
.cnx
├─ data.xlsx        ← 테이블 데이터(표준 xlsx)
├─ ct-schema.json   ← CT 열 타입 설정
├─ validation.json  ← 검증 규칙
├─ refs.json        ← 테이블 간 참조 / 외부 참조 소스
├─ formulas.py      ← 등록한 Python 수식
└─ meta.json        ← 프로젝트 메타데이터
```

> [!TIP]
> `.cnx` 내부 구조를 보려면 → 확장자를 `.zip`으로 바꿔 압축 해제하세요. 텍스트 부분은 모두 JSON이라 읽기 쉽고 diff도 가능합니다. 이것이 cnx가 Git 버전 관리에 적합한 이유입니다 — 내부가 모두 텍스트라 diff 친화적입니다.

## 주의 사항

> [!WARNING]
> 다른 도구로 cnx 내부의 xlsx를 수정하지 마세요 — ct-schema/validation과의 일관성이 깨집니다. 데이터를 수정할 때는 항상 ConfigNexus로 여세요.

> [!NOTE]
> cnx에는 **형식 버전 번호** 호환 문제가 없습니다 — v0.0.3에서 작성한 cnx를 v0.0.5로 열어도 읽힙니다. 다만 반대로(상위 버전 cnx를 하위 버전으로 읽기) 하면 일부 필드가 사라질 수 있습니다.
