# 멀티 탭 관리

A 테이블을 수정하다가 B 테이블에서 값 하나를 확인하려고 B 테이블을 열었더니, 방금 A 테이블의 선택 영역과 커서 위치가 전부 사라졌다 — 멀티 탭은 바로 이것을 해결합니다: 메인 창에서 **여러 테이블을 동시에 열고**, 각 테이블이 하나의 탭이 되어, 전환해도 각자의 편집 상태를 유지하며 서로 방해하지 않습니다.

## 탭 종류

| 종류 | 아이콘 | 의미 |
|------|--------|------|
| 일반 워크시트 | 📊 | xlsx / cnx 파일의 어떤 시트 |
| 환영 페이지 | 🏠 | 첫 페이지(이 페이지가 있는 곳) |
| 설정 | ⚙️ | 설정 센터 |
| 참조 관계 그래프 | 🔗 | 단일 인스턴스 재사용, [[참조 관계 그래프]] 참고 |

![멀티 탭 관리-탭 바](Res/zh/images/多页签管理-页签栏.png)

## 새 탭 열기

| 작업 | 설명 |
|------|------|
| 파일 브라우저에서 파일 더블 클릭 | 새 탭으로 열림 |
| 메뉴 파일 → 열기 | 파일 선택 → 새 탭 |
| 메뉴 파일 → 새로 만들기 | 빈 워크시트 → 새 탭 |
| 파일을 메인 창으로 드래그 | 자동으로 새 탭으로 열림 |
| 탭 바 맨 오른쪽 **+** 클릭 | 빈 워크시트 새로 만들기 |
| 환영 페이지 → 설정 클릭 | 단일 인스턴스 설정 페이지 |

## 탭 우클릭 메뉴

탭 위에서 우클릭:

- **닫기** —— 이 하나를 닫음
- **다른 탭 닫기** —— 이것만 남기고 나머지 모두 닫음
- **오른쪽 탭 모두 닫기** —— 이 탭의 오른쪽에 있는 모든 탭 닫음
- **경로 복사** —— 소스 파일 경로를 클립보드에 복사
- **파일 관리자에서 표시** —— 해당 파일이 있는 폴더로 이동

## 성능 최적화(중요)

ConfigNexus는 열자마자 모든 탭을 완전히 렌더링하지 않습니다 — 현재 활성화된 탭만 **실제로** Luckysheet 인스턴스를 렌더링합니다. 다른 탭으로 전환하면:

- 현재 탭의 Luckysheet 인스턴스는 **상태를 유지**(커서 위치, 선택 영역, 저장하지 않은 변경)
- 숨겨져 CPU를 차지하지 않음
- 다시 전환하면 즉시 복원

효과: 탭을 수십 개 열어도 메모리는 선형으로 증가하지만, CPU가 수십 개의 숨겨진 탭에 끌려가지 않습니다.

## 사전 렌더링 메커니즘

탭 전환 시 "Luckysheet 인스턴스 생성"에 걸리는 1-2초를 기다리지 않도록, 시스템은 숨겨진 인스턴스를 하나 **사전 렌더링**합니다:

- 시작 시 아무 테이블도 열지 않았다면, 백그라운드에서 빈 Luckysheet를 조용히 렌더링
- 사용자가 **+**를 누르면 사전 렌더링된 인스턴스를 바로 사용 → 즉시 표시
- 사용한 뒤 백그라운드에서 다음 것을 준비

이것이 "빈 탭 새로 만들기"가 거의 즉시 나타나는 이유입니다.

## 드래그 정렬

탭은 드래그로 정렬할 수 있습니다 — 탭 헤더를 길게 눌러 목표 위치로 가로로 드래그하세요.

## 저장하지 않은 변경 닫기

저장하지 않은 변경이 있는 탭을 닫으면 확인 대화상자가 뜹니다:

- **저장하고 닫기**
- **저장하지 않고 닫기**
- **취소**

설정에서 기본 동작을 바꿀 수 있습니다([[자동 저장]] 참고).

## 탭 개수 상한

이론상 무제한이지만 **동시에 20개를 넘기지 않기**를 권장합니다. 너무 많이 열면 탭 바가 빽빽해지고(가로 스크롤은 되지만) 전환 체감도 떨어집니다.

## 주의 사항

> [!TIP]
> 탭 전환 단축키: **Ctrl+Tab** 다음 / **Ctrl+Shift+Tab** 이전. 자주 쓰는 두 테이블 사이를 빠르게 오갈 수 있습니다.

> [!NOTE]
> 환영 페이지 / 설정 페이지 / 참조 관계 그래프는 모두 **단일 인스턴스**입니다 — 다시 열면 기존 탭으로 전환되고, 두 번째가 새로 열리지 않습니다.
