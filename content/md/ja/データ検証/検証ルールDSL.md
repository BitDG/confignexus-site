# 検証ルール DSL

ID 列に重複した ID を入れても気づかない、列挙列に存在しない値を入れても気づかない、テーブル間参照に削除済みの ID を入れたらなおさら気づかない——エクスポート後にプログラムがエラーを出すか、ゲーム実行時にクラッシュして初めて発覚します。検証ルール DSL はこれを解決します：ヘッダーの検証ルール行に小さな宣言（例えば `required`、`unique`、`ref(item@id)`）を書くと、その列全体がリアルタイムチェックの対象になり、入力ミスが即座に赤く表示され、エクスポートまで待つ必要がありません。

> [!tip]
> DSL（Domain-Specific Language、ドメイン固有言語）はここでは小さな「検証宣言の文字列」のこと——ヘッダーに書く、簡潔、バージョン管理可能、コピペできる。GUI でルールを組み立てるのではなく、文字どおりその数文字です。

## 8 つの組み込みルール

| ルール | 構文例 | 作用 |
|------|----------|------|
| `required` | `required` | 必須、空セルを赤く表示 |
| `unique` | `unique` | 列全体で一意、重複 ID 防止に必須 |
| `range(min, max)` | `range(1, 100)` | 数値が区間内であること |
| `enum(a, b, c)` | `enum(DAILY, WEEKLY, MONTHLY)` | これらの値のみ許可（固定列挙） |
| `enum_ref(テーブル@列)` | `enum_ref(item@id)` | 有効値が別テーブルのある列から動的に決まる |
| `len(min, max)` | `len(1, 50)` | 文字列長の制限 |
| `regex(pattern)` | `regex(^[A-Z]+$)` | 正規表現マッチ |
| `ref(テーブル@列)` | `ref(item@id)` | テーブル間参照の整合性——値が相手テーブルに存在すること |

## 組み合わせルール：`&&`

複数のルールを `&&` で連結し、左から右へ順に検証、すべて通過で合格：

```
required && range(0, 100)
```

意味：まず必須（空なら即赤）、次に 0〜100 をチェック（超えたら赤）。

```
required && unique && len(3, 20) && regex(^[a-z_]+$)
```

意味：必須＋全テーブル一意＋長さ 3〜20＋小文字とアンダースコアのみ、4 つすべて通過で合格。

## 最もよく使う 4 つの例

### 主キー ID 列

```
required && unique && range(1000, 99999)
```

必須・重複なし・指定区間内——この 1 行をコピーすれば使えます。

### 列挙型列（値を固定）

```
required && enum(DAILY, WEEKLY, MAIN, SIDE)
```

この 4 つの値しか入れられず、他を書くと赤くなります。

### 外部キー列（別テーブルを参照）

```
required && ref(item@id)
```

入力する ID は `item` テーブルの `id` 列に存在する必要があり、外部キー整合性が自動的に保証されます。

### 動的列挙列（有効値が別テーブル由来）

```
enum_ref(condition_type@id)
```

`condition_type` テーブルに新しい行を追加すると、この列の有効値セットも自動的に追従します——列挙リストを手動で保守する必要がありません。

## どこにルールを書くか

ヘッダーの**検証ルール行**（既定で 5 行目、行の役割が `validation`）。検証が必要な列の 5 行目のセルに、対応するルール文字列を書きます。

> [!tip]
> どの行が検証ルール行か分からない？デモプロジェクトをインポートして 5 行目の色分けを見るか、列ヘッダーを右クリック → CT 属性 → 現在の検証ルールを確認してください。

## エラーはどう表示されるか

- **リアルタイム赤表示**：ルール違反のセルは編集時に即座に赤くなり、検証実行を待つ必要なし
- **ホバー提示**：赤いセルにマウスを乗せると、tooltip でどのルールに違反したかを表示
- **検証ログ**：メニュー → 検証ログ、すべてのエラーを一覧し、**行をクリックすると対応セルへ直接ジャンプ**

## エクスポート前のブロック

エクスポート時（JSON / Protobuf など）にシステムが再度全テーブルを検証します。**error があればエクスポートをブロック**（warning はブロックしない）：

- ブロック（error）：`required` / `unique` / `ref` / `enum_ref` の違反
- 通すが提示（warning）：`range` / `len` / `regex` の違反

> [!tip]
> すべてのルールを error として扱いたい？設定 → データ検証 → 「緩和モード」をオフにします。

## パーサーの特性

- **括弧認識**：`regex(\(a\|b\))` は外側の `&&` で誤って分割されません
- **空白許容**：`required  &&  range( 0 , 100 )` は `required&&range(0,100)` と等価
- **大文字小文字の区別**：ルール名は小文字、パラメータはそのまま保持

## 注意事項

> [!warning]
> `ref` / `enum_ref` は参照先のテーブルがプロジェクト内で開かれている必要があります。参照先のテーブルがプロジェクト内にない場合は、**外部参照ソース**で取り込む必要があります（詳細は[[外部参照ソース]]）。

> [!note]
> 旧チュートリアル「データ検証」で説明していた GUI でのルール設定は v0.0.1 時代の古い方式で、v0.0.2 から DSL 文字列に統一されました。古い設定はアップグレード時に自動で DSL へ変換され、手動修正は不要です。
