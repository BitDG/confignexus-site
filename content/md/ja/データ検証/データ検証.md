# データ検証

設定テーブルデータの正確性と完全性を確保します。基本フォーマット検証と DSL ルール検証の 2 層チェック機構をサポートしています。

## 検証タイプ一覧

### 基本検証（自動）

| タイプ | 説明 | 例 |
|--------|------|-----|
| ID 一意性 | A 列の ID が重複しないこと | A5=1, A6=1 → エラー |
| 辞書フォーマット | `List<Dictionary>` は `[{key:value}]` 形式 | `[{1:100}]` ✓、`{1:100}` ✗ |
| 配列フォーマット | `int[]`/`float[]`/`string[]` は `[x,y]` 形式 | `[1,2,3]` ✓、`1,2,3` ✗ |

### DSL ルール検証（検証行で設定）

テーブル構造の**検証行**に DSL ルールを記述すると、システムが自動的にチェックします：

| ルール | 構文 | 例 |
|--------|------|-----|
| 必須 | `required` | フィールドを空にできない |
| 数値範囲 | `range(min,max)` | `range(0,100)` — 0〜100 の範囲内 |
| 列挙型 | `enum(a,b,c)` | `enum(warrior,mage,archer)` — この 3 つのみ |
| 文字列長 | `len(min,max)` | `len(1,50)` — 長さ 1〜50 |
| 正規表現 | `regex(pattern)` | `regex(^[A-Z]{3}_\d+$)` — パターンマッチ |
| 一意性 | `unique` | 列の値が重複しないこと |
| テーブル間参照 | `ref(テーブル@列)` | `ref(ItemConfig@id)` — 別テーブルに存在必須 |
| 列挙参照 | `enum_ref(テーブル@列)` | `enum_ref(TypeConfig@type)` — 別テーブルから列挙取得 |

#### ルールの組み合わせ

複数ルールは `&&` で連結し、すべてパスで合格：

```
required&&range(1,999)          → 必須かつ 1〜999 の範囲
required&&len(1,20)&&regex(^[a-z_]+$)  → 必須、長さ 1〜20、小文字+アンダースコアのみ
```

#### リスト要素の検証

列の型が `list<int>`、`list<string>` などの場合、ルールは各要素に対して自動適用されます：

```
列の型: list<int>    ルール: range(1,100)
値: [1,50,200]  → 要素 [2]: 数値 200 は範囲 [1, 100] 外
```

## 使い方

メニューバーの「データ検証」ボタンをクリックします。結果はログビューアの検証タブに表示されます。

## 検証範囲

各ワークシートの検証範囲はテーブル構造に基づきます：
- **開始列**：A 列
- **開始行**：データ開始行（テーブル構造定義に基づく、デフォルトは 5 行目）
- **終了範囲**：有効データの最終行・最終列まで
- **ID 終端**：A 列が空白の場合、その行以降は検証を停止

## ワークフローデモ

### ステップ 1：テーブル構造の設定

正しい行構造を確認します。デフォルト 5 行ヘッダー：

| 行 | 役割 | 例 |
|----|------|-----|
| 1 行目 | フィールド名 | id, name, type, price |
| 2 行目 | 表示名 | ID, 名前, タイプ, 価格 |
| 3 行目 | データ型 | int, string, int, float |
| 4 行目 | 説明 | ユニーク ID, アイテム名, カテゴリ, 購入価格 |
| 5 行目 | 検証ルール | required, required&&len(1,50), enum(1,2,3), range(0,9999) |
| 6 行目〜 | データ | 1, 鉄の剣, 1, 100.5 |

### ステップ 2：検証ルールの記述

検証行に DSL ルールを記入します：

```
A 列 (id):     required
B 列 (name):   required&&len(1,50)
C 列 (type):   required&&enum(1,2,3)
D 列 (price):  range(0,9999)
E 列 (ref_id): ref(ItemConfig@id)
```

### ステップ 3：検証の実行

「データ検証」ボタンをクリックすると、システムが以下を実行します：
1. すべてのワークシートを巡回
2. 各シートの検証行ルールを読み取り
3. 各データセルに対して対応ルールを実行
4. エラーをログビューアに出力

### ステップ 4：確認と修正

ログパネルの「検証」タブに結果が表示されます：
- エラー項目をクリックすると対応セルにジャンプ
- エラーレベル：具体的なルール失敗理由を表示
- 修正提案：各エラーに解決策が付属

## テーブル間参照の検証

`ref()` と `enum_ref()` はワークシート間の検証をサポートします：

```
シナリオ：アイテムテーブルの type フィールドがタイプ設定テーブルを参照

アイテムテーブル検証行 C 列:  ref(TypeConfig@id)
  → "TypeConfig" という名前のワークシートを検索
  → その "id" 列のすべての値を読み取り
  → 現在の列の各値がそのセットに存在するか検証
```

## カスタムルールの拡張

DSL ルール以外にも、コードでカスタム検証関数を登録できます：

```javascript
window.validator.config.customRules = [
  {
    validate: (value, cellConfig) => {
      if (cellConfig.type === 'int' && value % 2 !== 0) {
        return 'この列には偶数のみ許可されています';
      }
      return true;
    }
  }
];
```
