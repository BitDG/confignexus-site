# cnx プロジェクトファイル

毎日 xlsx でプロジェクトを保存していると、開くたびに CT 列タイプを設定し直し、検証ルールは消え、前回書いた Python 数式が見つからない——これは xlsx がこれらの設定を保持できないからです。`.cnx` は ConfigNexus の**ネイティブプロジェクトファイル**：テーブルデータ、CT タイプ、検証ルール、テーブル間参照、Python 数式をすべて 1 つのファイルにまとめ、**閉じて開き直してもすべて残ります**。

下のボタンでデモプロジェクトをインポートして、.cnx を開くとどう見えるかを確認してみましょう：

createtab:Res/zh/templates/富文本编辑演示.cnx

## .xlsx との違い

| 項目 | .xlsx | .cnx |
|------|-------|------|
| ファイルサイズ | 同等データなら小さめ | 大きめ（メタデータを含む） |
| 数式 | ✅ Excel 数式 | ✅ Excel 数式 + Python 数式 |
| スタイル | ✅ | ✅ |
| セル結合 | ✅ | ✅ |
| CT 列タイプ | ❌ インポート時に失われる | ✅ 完全に保持 |
| テーブル間参照 | ❌ | ✅ |
| 外部参照ソース設定 | ❌ | ✅ |
| リッチテキスト / JSON ビュー状態 | ❌ | ✅ |
| 検証ルール DSL | ❌ エクスポート時に通常テキストへ退化 | ✅ |
| Excel で開ける互換性 | ✅ | ❌ |

**要するに**：長期プロジェクトは `.cnx`、外部協業や最終納品は `.xlsx` を使います。

## いつ cnx を使うか

- ✅ 日常のプロジェクトファイル（自分やチームが ConfigNexus 内で編集するもの）
- ✅ Git でバージョン管理にコミットするソースファイル
- ✅ CT 列 / 検証ルール / Python 数式を保持したい場面

## いつ cnx を使わないか

- ❌ プログラマーに見せる（開けないので、先に json/xlsx へエクスポートが必要）
- ❌ ConfigNexus 非利用者に見せる
- ❌ メール / IM での一時共有（xlsx の方が汎用的）

## cnx プロジェクトを新規作成

メインウィンドウメニュー → **ファイル → 新規 cnx プロジェクト** → 保存場所を選択 → 既定の sheet を 1 つ含む空の `.cnx` が自動作成されます。

## xlsx から cnx へ変換

メインウィンドウで xlsx を開く → メニュー → **ファイル → cnx として保存** → 保存場所を選択。

変換後：

- すべてのデータが保持される
- 通常の数式が保持される
- スタイルが保持される
- CT 列タイプは**再設定が必要**（xlsx にこの情報がないため）
- 検証ルールは**書き直しが必要**

## cnx から xlsx へ変換（エクスポート）

メニュー → **ファイル → エクスポート → xlsx** → 出力パスを選択。

退化するもの：

- CT 列タイプ → 通常の文字列列に退化
- Python 数式 → **エクスポートされない**（xlsx に Python 実行環境がないため）
- 検証ルール DSL → xlsx の「データの入力規則」に変換（一部のルールは変換可、複雑なルールは失われる）

## ダブルクリック関連付け

ConfigNexus は `.cnx` のダブルクリック関連付けを登録しています——ファイルマネージャーで `.cnx` ファイルをダブルクリックすると ConfigNexus で直接開きます。

## ファイル内部構造

`.cnx` は本質的に zip です：

```
.cnx
├─ data.xlsx        ← テーブルデータ（標準 xlsx）
├─ ct-schema.json   ← CT 列タイプ設定
├─ validation.json  ← 検証ルール
├─ refs.json        ← テーブル間参照 / 外部参照ソース
├─ formulas.py      ← 登録済みの Python 数式
└─ meta.json        ← プロジェクトメタデータ
```

> [!TIP]
> `.cnx` の内部構造を見たい → 拡張子を `.zip` に変えて解凍。テキスト部分はすべて JSON で、可読かつ diff 可能です。これが cnx が Git バージョン管理に向いている理由——内部がすべてテキストで diff フレンドリーだからです。

## 注意事項

> [!WARNING]
> 別のツールで cnx 内部の xlsx を直接変更しないでください——ct-schema/validation との整合性が壊れます。データを変更するときは必ず ConfigNexus で開いてください。

> [!NOTE]
> cnx に**フォーマットバージョン番号**の互換性問題はありません——v0.0.3 で書いた cnx を v0.0.5 で開いても読めます。ただし逆方向（高バージョンの cnx を低バージョンで読む）はフィールドが失われる可能性があります。
