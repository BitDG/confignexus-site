# 永続スクリプトライブラリ

新しいプロジェクトを開くたびに、前回調整したスクリプト一式を書き直す？せっかく書いた数式関数があちこちのプロジェクトに散らばって見つからない？スクリプトライブラリはこれを専門に解決します：スクリプトエディタで書いたスクリプト / 登録した数式関数を、**一度保存すればプロジェクトをまたいで永久に再利用**でき、書き直す必要がなくなります。

## スクリプトライブラリを開く

メインウィンドウメニュー → **ツール → スクリプトライブラリ**

または Python スクリプトエディタ上部の **スクリプトライブラリ** ボタンをクリック。

## スクリプトライブラリパネル

開くと、カテゴリごとにグループ化されたスクリプト一覧が表示されます：

![スクリプトライブラリパネル](Res/zh/images/脚本库面板.png)

- **グループ化**：「機能カテゴリ」タグで自動グループ化
- **スコープ切り替え**：グローバル（すべてのプロジェクトで使える） / 現在のプロジェクト専用
- **有効化 / 無効化**：無効化すると関数は呼び出せなくなるが、設定は保持
- **検索**：上部の検索ボックスでスクリプト名 / タグ / 説明をフィルター

## スクリプトのメタデータ

各スクリプトはコード本体のほかに以下を持ちます：

| フィールド | 必須 | 説明 |
|------|------|------|
| 名前 | ✅ | 数式呼び出し名、一意 |
| カテゴリタグ | ❌ | グループ化用（数値計算 / 文字列処理 / ...） |
| 説明 | ❌ | hover 提示 / ドキュメント生成用 |
| 作者 | ❌ | 誰が書いたか |
| バージョン | ❌ | チーム同期用 |
| スコープ | ✅ | グローバル / 現在のプロジェクト |

## プロジェクト間同期

**グローバル**スクリプトは `~/.configNexus/scripts/global/` に保存され、すべてのプロジェクトで共有されます。

**現在のプロジェクト**スクリプトは `<プロジェクト>/scripts/local/` に保存され、プロジェクトに付随します（Git バージョン管理への組み込みを推奨）。

## ワークショップとの連携

スクリプトライブラリのスクリプトは**コンポーネントとしてパッケージ化**して Steam ワークショップにアップロードできます：

1. パッケージ化したいスクリプトをいくつか選ぶ
2. **コンポーネントとしてパッケージ化** → コンポーネントメタデータを入力
3. ワークショップにアップロード

他のユーザーが購読すると、これらのスクリプトが自動的に彼のスクリプトライブラリに現れます。

## スクリプトの依存

スクリプト同士は互いに呼び出せます：

```python
# スクリプト A：基礎ツール
def round_to(value, step):
    return round(value / step) * step

# スクリプト B：A を呼ぶ
from script_lib import round_to  # 特殊なインポート構文で

def calc_price(base, level):
    raw = base * (1 + level * 0.1)
    return round_to(raw, 0.1)
```

> [!NOTE]
> `from script_lib import xxx` は ConfigNexus 独自のインポート構文——スクリプトライブラリから他のスクリプトをインポートできます。通常の Python `import` ではできません。

## ドキュメント生成

スクリプトライブラリパネル右上の **ドキュメント生成** → Markdown ファイルをエクスポートし、すべてのスクリプト＋説明＋シグネチャを一覧します。以下に適します：

- チームのオンボーディング資料
- プログラマーに「プランナー側がどんな関数を使えるか」を見せる

## セキュリティ

スクリプトはサンドボックス内で実行されます（詳細はチュートリアル[[Pythonスクリプトエディタ]]）。スクリプトライブラリでも同じ制限があります：

- `open()` でファイルを開けない
- `subprocess` 不可
- `os.environ` の変更不可

あるスクリプトが例外的に許可を必要とする場合（まれ）、スクリプトのメタデータで「権限昇格」を申請すると、起動時に確認ダイアログが出ます。

## 注意事項

> [!WARNING]
> スクリプトの削除は**復元不可**です——ローカルファイルも同時に削除されます。重要なスクリプトは先に Git でバックアップするか、エクスポートしてから削除してください。

> [!TIP]
> 命名のおすすめ：動詞始まり・小文字スネークケース（`calc_exp` / `validate_id` / `gen_localized_key`）。セル数式から呼ぶときに最も自然に見えます。
