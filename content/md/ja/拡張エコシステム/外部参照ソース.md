# 外部参照ソース

プランナーが A テーブルにアイテム ID を入れたいが、アイテムのマスターテーブルは別のプロジェクトにある——以前は記号で手書き写しするか、2 つの Excel を並べて見比べるしかありませんでした。外部参照ソースは「別プロジェクトのテーブル」を取り込み、本プロジェクトの数式 / 検証 / 自動補完が相手のデータを直接参照できるようにします。対応関係を手動で保守する必要はありません。

プロジェクト外のファイル / フォルダを「参照ソース」として登録し、数式 / 検証 / 自動補完がプロジェクトをまたいでテーブルを引けるようにします——例えば別プロジェクトの `talent.xlsx` を追加すると、本プロジェクトの `id` 列で相手の ID をドロップダウンから選べます。

## 機能の全体像

| 機能 | 説明 |
|------|------|
| 複数ソース対応 | 複数のファイル / フォルダを同時に参照ソースとして取り込む |
| エイリアス機構 | 各ソースに覚えやすい表示名を付け、ドロップダウンで見分けやすく |
| 競合解決 | 複数ソースに同名のテーブル / 列があるとき、設定でどれを優先するか指定可 |
| 再帰スキャン | フォルダソースは「第 1 階層のみ」か「すべてのサブディレクトリ」を選べる |
| 増分更新 | 個別のソースだけを単独更新でき、全部を再読み込みしなくてよい |

## 参照ソースを追加

### 方法 1：ファイルブラウザの右クリック

ファイルブラウザで任意のファイルまたはフォルダを右クリック → **🔗 外部参照ソースとして追加** → 表示名を入力 → フォルダの場合は再帰方式を確認。

### 方法 2：設定ページ

メインウィンドウ **設定 → 外部参照ソース** → **+ 追加** をクリック → ファイルまたはフォルダを選択。

## エイリアス vs 表示名

| 概念 | 何か | 使い方 |
|------|--------|--------|
| 表示名 | この参照ソースに付けるラベル | ドロップダウンでソースを区別 |
| エイリアス | ソース内で発見された各参照キー | 数式 / CT 列から直接呼び出す |

例：`プロジェクトB/talent.xlsx` を追加し、表示名を「プロジェクトB 才能」とします。システムがスキャンしてエイリアス `talent` を登録すると——本プロジェクトで `=lookup('talent', 'id', 1001)` で相手のデータを引けます。

## 競合解決

2 つのソースが両方ともエイリアス `talent` を登録した場合：

1. 設定ページ → 外部参照ソース → ⚠ バッジ付きのソースを確認
2. 「競合リスト」を開く
3. 競合する各エイリアスについて優先ソースを 1 つ選ぶ（または片方をリネーム）

競合が未解決のまま、そのエイリアスを呼ぶと**最後に追加した**ソースが使われます（警告ログ付き）。

## 更新の仕組み

- 個別ソースの更新：設定ページでそのソースの 🔄 をクリック
- 全部更新：設定ページ上部の **🔄 すべて更新**
- ソースファイルを変更しても**自動では**再スキャンされません——手動で更新が必要です

> [!TIP]
> 参照ソースのスキャン結果はプロジェクトローカルにキャッシュされ、セッションをまたいで保持されます。大きなフォルダ（数百個の xlsx）を初めて追加するときは数秒かかることがあります。

## 削除 / 無効化

- **無効化**：このソースを一時的にテーブル参照に参加させないが、設定は保持（設定ページでスイッチ）
- **削除**：完全に除去（削除後は、このソースを参照していた数式は値を引けなくなる）

## 数式との統合

セルに書く：

```
=lookup('<エイリアス>', '<列名>', <主キー値>)
```

`<エイリアス>` は登録済みの参照ソースエイリアスでなければなりません。エイリアス競合が未解決の場合、関数は「最後に追加」の原則で解決し warning を出します。

## 注意事項

> [!WARNING]
> 外部参照ソースは**読み取り専用**です——それを通じて引いたデータは本プロジェクト内で直接変更できません。相手の値を変えるには、相手のファイルを開く必要があります。

> [!NOTE]
> 旧プロジェクトの mapping 設定はアップグレード時に外部参照ソースへ**自動移行**され、手動でやり直す必要はありません。移行結果がおかしいと感じたら、設定ページ → 外部参照ソース → 高度な設定 → 「旧 mapping から再インポート」できます。
