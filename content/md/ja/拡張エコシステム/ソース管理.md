# ソース管理（Git / SVN）

プランナーがあるアイテムの数値を変えた。午後にプログラマーが来て「どの行を変えた？」と聞く。記憶やスクショ比較で答えるしかない——こうした非効率な協業はどのチームも経験します。設定テーブルを Git / SVN に組み込むと、コードにバージョン履歴があるのと同じように：誰がいつどのセルを変え、変更前と後がそれぞれ何だったか、1 本の log ですべて見えるようになり、もう記憶頼みは不要です。

ConfigNexus は Git / SVN クライアントパネルを内蔵しています——設定テーブルもコードであり、バージョン管理に組み込めば「誰がどの値を変えたか」が明確に追えます。パネルはファイルブラウザの左側サイドバーに常駐します。

## 機能の全体像

| 機能 | Git | SVN |
|------|-----|-----|
| 変更リスト | ✅ ステージ済み / 未ステージ / 未追跡の 3 欄 | ✅ 単一の変更欄（SVN に staging 概念なし） |
| コミット | ✅ | ✅ |
| プル / 更新 | ✅ pull | ✅ update |
| プッシュ | ✅ push | — （SVN commit は直接サーバーへ） |
| 取り消し | ✅ discard / revert | ✅ revert |
| ブランチ管理 | ✅ branches / checkout / create / delete / merge | — |
| 下書き退避 | ✅ stash / stash pop | — |
| 履歴閲覧 | ✅ log + diff | ✅ log + diff |
| ファイルバッジ | ✅ M / A / D / U / C | ✅ M / A / D / ? / C |

## 前提条件

- **Git**：システム PATH に `git` コマンドがある（[Git for Windows](https://git-scm.com/) をインストールすると既定で入る）
- **SVN**：システム PATH に `svn.exe` がある（TortoiseSVN インストール時に **command line client tools** オプションをチェックすると入る）

> [!NOTE]
> 未インストールでも問題ありません——ConfigNexus は起動時に自己診断し、未インストールのプラグインは自動でアイコンを隠すので、他の機能には影響しません。

## パネルを開く

ファイルブラウザ左側の縦並びアイコンバー：

- 🌿 → Git ソース管理パネル
- 🌐 → SVN ソース管理パネル

## バッジシステム

ファイルブラウザのファイル名の横に、バージョン管理状態が自動表示されます：

| バッジ | 意味 |
|------|------|
| M | 変更済み |
| A | 新規追加 |
| D | 削除済み |
| U / ? | 未追跡 |
| C | 競合 |

バッジは 30 秒キャッシュされ、commit / 取り消し操作後は即座に更新されます。

## Git パネルの操作

### コミットフロー

1. **未ステージ** 欄に今回の変更が並ぶのを見る
2. ファイル名をシングルクリックして diff を確認
3. ファイル名右側の **+** でステージ（ステージ済み欄へ移動）
4. 下部の入力欄に commit message を書く
5. **コミット** をクリック → 完了

### ブランチ管理

パネル上部のブランチ名横の 🌿 chip → ブランチ popover を表示：

- すべてのローカル / リモートブランチを一覧
- 現在のブランチの前に ⭐
- 別のブランチをクリック → 切替（未コミットの変更があれば先に提示）
- **+ 新規ブランチ** で名前を入力 → 新ブランチへ自動 checkout

### 下書き退避（stash）

コミットはしたくないがブランチを切り替えたいとき：

1. パネルツールバーで **現在の変更を退避** を押し、備考を入力 → stash にプッシュ
2. 別のブランチで作業
3. 元のブランチに戻る → ツールバーで **最新の下書きを取り出す** → 変更が復元

## SVN パネルの操作

### コミットフロー

1. 変更リストでコミットするファイルにチェック
2. 下部に commit message を入力
3. **コミット** をクリック → 直接 SVN サーバーへ送信（SVN にローカル staging 概念なし）

### サーバー最新へ同期

ツールバー **⬇ 更新** → サーバー最新版をローカルへ取得。

## パフォーマンス最適化

v0.0.3 から、Git / SVN のバッジと変更リストは「リポジトリ全体スナップショットキャッシュ＋リクエストマージ」を採用しています：

- 初回は `git status` / `svn status` を 1 回照会
- 30 秒以内のすべてのファイルのバッジ照会はキャッシュ経由
- commit / pull / 取り消しなどの操作後はキャッシュが自動失効

効果：数百ファイルのディレクトリでも、ファイルブラウザを開く際に**もう固まりません**。

## scope の限定

ソース管理パネルは既定で**リポジトリ全体**の変更を一覧します。**現在のファイルブラウザのロケーション**下の変更だけを一覧させることもできます：

- パネル上部の **現在の範囲** chip で「リポジトリ全体 / 現在ディレクトリ」を切替
- 設定テーブルプロジェクトが大きく変更ファイルが多いときは「現在ディレクトリ」への切替を強く推奨

## 大きな変更リスト（10000+ ファイル）

万単位の変更時、パネルは自動的にページングします：

- 各グループは先頭 200 件だけ表示
- 下部に **もっと読み込む (+200)** / **すべて表示** ボタン
- 一度に 10000 個の DOM ノードを詰め込んでブラウザを固めることはしない

## テーブル diff 統合

**テーブル差分 DLC** をインストールしている場合：

- 変更リストの `.xlsx` / `.cnx` ファイルをクリック → 「テーブルで diff するか、テキストで diff するか」を表示
- テーブル diff：HEAD 版と作業領域版を比較し、セル単位でハイライト
- テキスト diff：通常の unified diff

詳細はチュートリアル[[テーブル差分]]。

## 注意事項

> [!WARNING]
> 変更の取り消しは**復元不可**です——`git checkout --` も `svn revert` もファイルを前回コミットの状態に戻し、未保存の作業はそのまま失われます。システムは先に確認ダイアログを出しますが、押す前に本当にその変更が要らないか確認してください。

> [!TIP]
> Git 履歴のある commit を開く → その commit でどのファイルが変わったか＋各ファイルの diff が見えます。作業領域と比較したいなら **HEAD 比較** ツールを使います（テーブル差分のページで説明）。
