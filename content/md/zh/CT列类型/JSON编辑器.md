# JSON 编辑器

奖励配置塞进格子长这样：`{"items":[{"id":1001,"rate":0.5}],"gold":50}` ——格子太窄看不全，手改括号少一个引号程序直接崩，多层嵌套更不知道改哪一层。JSON 编辑器就是干这个的：把某列设成 JSON 类型，双击格子弹出 Monaco 代码视图 + 树状图双视图，左边改代码右边树立即同步、右边点节点左边光标跟过去，格式不对时保存按钮直接置灰，坏 JSON 写不进格子。

> [!tip]
> JSON（JavaScript Object Notation，轻量数据交换格式）适合存嵌套结构——奖励列表、道具属性、关卡参数。简单的"对象数组、每条结构固定"用**多数据编辑**更直观（详见[[多数据编辑]]）。

## 怎么用

### 第 1 步：把某列设成 JSON 编辑器

选中目标列任意一格 → **右键** → **CT 属性 → 设置为 JSON 编辑器**。整列一次生效。

> [!note]
> CT 属性（Column Type，列类型）给"这列装什么数据"贴标签，设一次整列都管。演示工程里的 `drops` 列（D 列）就是用来挂 JSON 编辑器的，右键 D 列任意格即可设置。

### 第 2 步：双击数据格打开编辑器

在 JSON 列里**双击数据行的格子**，Monaco + 树状图弹窗就出来了。

> [!warning]
> 只有**数据行**双击才弹。表头区（字段名/类型/验证规则那几行）双击不弹——跟富文本编辑器一样，故意的，免得把表头当数据改。

### 第 3 步：在双视图里编辑

左侧 Monaco 代码视图（跟 VS Code 同款编辑器），直接改 JSON 文本；右侧树状视图自动同步，逐层展开，点节点光标跳到对应行。

![JSON编辑器双视图](Res/zh/images/JSON编辑器双视图.png)

常用树视图操作：

| 操作 | 效果 |
|------|------|
| 点节点 | 左侧编辑器光标定位到该行 |
| 双击节点 | 弹小窗单独编辑这个值（数字/字符串/布尔有对应控件） |
| 右键节点 | 新增子节点 / 删除 / **复制路径** / 折叠所有 |
| 拖动节点 | 调整数组元素顺序 |

### 第 4 步：确认格式、保存

底部状态栏实时显示 JSON 是否合法——合法显示节点数和最深层数，有错显示错误行 + 描述。**格式有误时保存按钮置灰**，必须修正才能写回格子。

> [!tip]
> 常见小错误（尾逗号 `[1,2,]`、单引号 `{'key':'val'}`）编辑器会**先尝试自动修复**再打开；自动修复不了才报错并定位到问题行。演示工程里第 7 行（精英哥布林）预置了一个尾逗号，打开就能看到自动修复效果；第 8 行（骷髅兵）是不完整 JSON，会看到报错定位。

## 值类型颜色标注

树视图里每个值有颜色区分类型：

| 类型 | 颜色 | 示例 |
|------|------|------|
| 字符串 | 紫色 | `"装备掉落"` |
| 数字 | 蓝色 | `100` |
| 布尔 | 橙色 | `true` |
| null | 灰色 | `null` |
| 数组 | 绿色 | `[3]`（3 个元素） |
| 对象 | 绿色 | `{2}`（2 个字段） |

类型不会在双向同步时被意外改变——除非你手动改代码区。

## JSON 编辑器 vs 多数据编辑

| 场景 | 用哪个 |
|------|--------|
| 单元格里是一个 JSON 对象 / 嵌套任意结构 | JSON 编辑器 |
| 单元格是对象数组、每条结构固定（如奖励列表） | 多数据编辑（schema 驱动，列对齐更直观） |
| 临时探索 / 结构不确定 | JSON 编辑器（更灵活） |

## 注意事项

> [!tip]
> 树节点右键 → **复制路径**，能拿到 `rewards[0].count` 这样的 JSONPath，可以直接用在 Python 公式 `=json_get('rewards[0].count')` 里自动读值。

> [!warning]
> 单元格里塞几 MB 大 JSON 时编辑器可能加载慢——这类大结构更适合放外部 `.json` 文件用**外部引用源**挂进来（详见[[外部引用源]]）。

> [!note]
> "这列是 JSON 编辑器列"这个设置（CT 属性）是列的元数据，存在 `.cnx` 里，不会当成字段导出。存 `.cnx` 能留住列类型，存 `.xlsx` 会丢。详见[[Cnx工程文件]]。
