# 源代码管理（Git / SVN）

策划改了某个道具数值，下午程序来问"你改了哪几行"，只能靠记忆或截图对比——这种低效协作每个团队都经历过。把配置表纳入 Git / SVN 就像让代码有版本历史一样：谁在什么时间改了哪个格子、改前改后分别是什么，一条 log 全看到，再也不用靠记忆。

ConfigNexus 内置了 Git / SVN 客户端面板——配置表也是代码，把它们纳入版本控制能让"谁改了哪个值"清晰可查。面板挂在文件浏览器的左侧侧边栏。

## 功能总览

| 功能 | Git | SVN |
|------|-----|-----|
| 改动列表 | ✅ 已暂存 / 未暂存 / 未跟踪三栏 | ✅ 单一改动栏（SVN 无 staging 概念） |
| 提交 | ✅ | ✅ |
| 拉取 / 更新 | ✅ pull | ✅ update |
| 推送 | ✅ push | — （SVN commit 直接到服务器） |
| 撤销 | ✅ discard / revert | ✅ revert |
| 分支管理 | ✅ branches / checkout / create / delete / merge | — |
| 暂存草稿 | ✅ stash / stash pop | — |
| 历史查看 | ✅ log + diff | ✅ log + diff |
| 文件角标 | ✅ M / A / D / U / C | ✅ M / A / D / ? / C |

## 前置条件

- **Git**：系统 PATH 上有 `git` 命令（装 [Git for Windows](https://git-scm.com/) 时默认会装）
- **SVN**：系统 PATH 上有 `svn.exe`（装 TortoiseSVN 时**勾上 command line client tools** 选项才会装）

> [!NOTE]
> 没装也没关系——ConfigNexus 启动时自检，没装的插件会自动隐藏图标，不影响其他功能。

## 打开面板

文件浏览器左侧竖排图标栏：

- 🌿 → Git 源代码面板
- 🌐 → SVN 源代码面板

## 角标系统

文件浏览器里的文件名旁边会自动显示版本控制状态：

| 角标 | 含义 |
|------|------|
| M | 已修改 |
| A | 新增 |
| D | 已删除 |
| U / ? | 未跟踪 |
| C | 冲突 |

角标缓存 30 秒；做完 commit / 撤销动作角标会立即刷新。

## Git 面板操作

### 提交流程

1. 看 **未暂存** 区列出本次改动
2. 单击文件名查看 diff
3. 点文件名右侧 **+** 暂存（移到已暂存区）
4. 在底部输入框写 commit message
5. 点 **提交** → 完成

### 分支管理

面板顶部分支名旁的 🌿 chip → 弹出分支 popover：

- 列出所有本地 / 远程分支
- 当前分支前面有 ⭐
- 点其他分支 → 切换（有未提交改动会先提示）
- **+ 新建分支** 输入名字 → 自动 checkout 到新分支

### 暂存草稿（stash）

不想 commit 但要切分支时：

1. 面板工具栏点 **暂存当前改动** 输入备注 → stash 进栈
2. 切别的分支干活
3. 切回原分支 → 工具栏点 **取出最近草稿** → 改动恢复

## SVN 面板操作

### 提交流程

1. 改动列表里勾选要提交的文件
2. 底部输入 commit message
3. 点 **提交** → 直接发到 SVN 服务器（SVN 没有本地 staging 概念）

### 同步服务器最新

工具栏 **⬇ 更新** → 拉取服务器最新版本到本地。

## 性能优化

v0.0.3 起，Git / SVN 角标和改动列表用了"整仓快照缓存 + 请求合并"：

- 第一次打开会查一次 `git status` / `svn status`
- 30 秒内所有文件的角标查询走缓存
- 做完 commit / pull / 撤销 等动作缓存自动失效

效果：一个有几百个文件的目录，打开文件浏览器**不再卡顿**。

## scope 限定

源代码面板默认列**整个仓库**的改动。你可以让它只列**当前文件浏览器位置**下的改动：

- 面板顶部 **当前范围** chip 切换"整仓 / 当前目录"
- 配置表项目大、改动文件多时强烈推荐切到"当前目录"

## 大改动列表（10000+ 文件）

万级改动时面板会自动分页：

- 每组只显示前 200 条
- 底部有 **加载更多 (+200)** / **显示全部** 按钮
- 不会一次性塞 10000 个 DOM 节点把浏览器卡死

## 表格 diff 集成

如果装了 **数据表对比 DLC**：

- 点改动列表里的 `.xlsx` / `.cnx` 文件 → 弹"按表格 diff 还是按文本 diff"
- 按表格 diff：HEAD 版本和工作区版本对比，单元格级 highlight
- 按文本 diff：普通 unified diff

详见教程[[数据表对比]]。

## 注意事项

> [!WARNING]
> 撤销改动是**不可恢复**的——`git checkout --` 和 `svn revert` 都会把文件恢复到上次提交的状态，未保存的工作直接丢失。系统会先弹确认框，但点之前请确认你真的不要这些改动。

> [!TIP]
> Git 历史里的某个 commit 点开 → 看到的是这次 commit 改了哪些文件 + 每个文件的 diff。如果想跟工作区比较，用 **HEAD 对比** 工具（数据表对比那一篇有讲）。
