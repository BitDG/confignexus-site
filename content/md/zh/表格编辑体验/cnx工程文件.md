# cnx 工程文件

天天用 xlsx 存工程，结果每次打开都要重设一遍 CT 列类型、验证规则消失了、Python 公式上次写的找不到——这是因为 xlsx 根本装不下这些配置。`.cnx` 是 ConfigNexus 的**原生工程文件**：把表格数据、CT 类型、验证规则、跨表引用、Python 公式全打包在一个文件里，**关掉重开什么都在**。

点下面按钮导入一个演示工程，马上看看 .cnx 打开是什么样：

createtab:Res/zh/templates/富文本编辑演示.cnx

## 跟 .xlsx 的区别

| 维度 | .xlsx | .cnx |
|------|-------|------|
| 文件大小 | 同等数据下较小 | 较大（含元数据） |
| 公式 | ✅ Excel 公式 | ✅ Excel 公式 + Python 公式 |
| 样式 | ✅ | ✅ |
| 合并单元格 | ✅ | ✅ |
| CT 列类型 | ❌ 导入时丢失 | ✅ 完整保留 |
| 跨表引用 | ❌ | ✅ |
| 外部引用源配置 | ❌ | ✅ |
| 富文本 / JSON 视图状态 | ❌ | ✅ |
| 验证规则 DSL | ❌ 导出时退化为普通文本 | ✅ |
| 兼容 Excel 打开 | ✅ | ❌ |

**简而言之**：长期工程用 `.cnx`，跟外部协作或最终交付用 `.xlsx`。

## 什么时候用 cnx

- ✅ 日常工程文件（你和团队同事在 ConfigNexus 里改的）
- ✅ Git 提交进版本控制的源文件
- ✅ 需要保留 CT 列 / 验证规则 / Python 公式的场景

## 什么时候不用 cnx

- ❌ 给程序员看（他们打不开，得先导出成 json/xlsx）
- ❌ 给非 ConfigNexus 用户看
- ❌ 邮件 / IM 临时分享（用 xlsx 更通用）

## 新建 cnx 工程

主窗口菜单 → **文件 → 新建 cnx 工程** → 选保存位置 → 自动新建一个空的 `.cnx`，包含一个默认 sheet。

## 从 xlsx 转 cnx

主窗口打开 xlsx → 主窗口菜单 → **文件 → 另存为 cnx** → 选保存位置。

转过去之后：

- 所有数据保留
- 普通公式保留
- 样式保留
- CT 列类型**需要重新挂**（xlsx 里没有这个信息）
- 验证规则**需要重新写**

## cnx 转 xlsx（导出）

主窗口菜单 → **文件 → 导出 → xlsx** → 选输出路径。

退化的东西：

- CT 列类型 → 退化为普通字符串列
- Python 公式 → **不导出**（xlsx 里没有 Python 运行环境）
- 验证规则 DSL → 转为 xlsx 的"数据有效性"（部分规则能转，复杂规则会丢）

## 双击关联

ConfigNexus 注册了 `.cnx` 的双击关联——文件管理器里双击 `.cnx` 文件直接用 ConfigNexus 打开。

## 文件内部结构

`.cnx` 本质是个 zip：

```
.cnx
├─ data.xlsx        ← 表格数据（标准 xlsx）
├─ ct-schema.json   ← CT 列类型配置
├─ validation.json  ← 验证规则
├─ refs.json        ← 跨表引用 / 外部引用源
├─ formulas.py      ← 注册过的 Python 公式
└─ meta.json        ← 工程元数据
```

> [!TIP]
> 想看 `.cnx` 内部结构 → 把扩展名改成 `.zip` 解压。文本部分都是 JSON，可读可 diff。这也是为什么 cnx 适合 Git 版本控制——内部都是文本，diff 友好。

## 注意事项

> [!WARNING]
> 不要用别的工具改 cnx 内部的 xlsx——会破坏跟 ct-schema/validation 的一致性。要改数据始终用 ConfigNexus 打开。

> [!NOTE]
> 没有 cnx **格式版本号** 兼容问题——v0.0.3 写的 cnx 用 v0.0.5 打开也能读。但反过来（高版本 cnx 用低版本读）可能丢字段。
