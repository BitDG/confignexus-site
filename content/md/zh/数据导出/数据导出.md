# 数据导出

表填好了，程序要 JSON、引擎要二进制、策划 review 要 CSV——每种格式手工转一遍，慢不说还容易搞出版本不一致。ConfigNexus 数据导出一次搞定：**10 种格式勾选即导**，覆盖文本、代码、二进制三大类，Unity / Unreal / Godot / 自研引擎都能直接吃，支持同时导多种格式。

## 支持的格式

> 主窗口 **文件 → 导出数据** 打开导出面板，勾选下面任意格式即可一键导出（支持多选）。

### 文本格式

| 格式 | 用途 | 文件扩展 |
|------|------|---------|
| JSON | 通用、Web、Node.js 工具链 | `.json` |
| YAML | 配置文件、CI、人读 | `.yaml` |
| CSV | Excel / 数据库 / 简单工具 | `.csv` |

### 代码文件（自带加载器）

| 格式 | 用途 |
|------|------|
| C# 数据类 | Unity 项目直接接，自带 MessagePack 注解 |
| TypeScript | 接口 + 加载器 + JSON 数据，前端 / Node 项目直接 import |
| Lua | 自带数据的加载器模块，接 Lua 引擎 / 自研 |
| C++ | 结构体 + 加载器 + JSON 数据，接 Unreal / 自研 C++ 引擎 |

C# 数据类自带 [MessagePackObject] 注解，跟二进制 MessagePack 配套；也支持 [Key(N)] / [IgnoreMember] 等特性细控。

### 二进制格式

| 格式 | 用途 | 大小 vs JSON |
|------|------|--------------|
| Bytes（自定义紧凑） | 内部传输、游戏内嵌 | -40% |
| MessagePack | 跨语言、生态广 | -45% |
| Protobuf | 跟 .proto 配套，Google 二进制 | -50% |

## 配置导出路径

主窗口 → **设置 → 导出配置** → 为每种格式设默认输出目录。一次配置好，以后导出直接走，不用每次选文件夹。

支持模板变量：

- `{project}` → 当前项目名
- `{sheet}` → 工作表名
- `{date}` → YYYY-MM-DD
- `{branch}` → 当前 Git 分支（如果是 Git 项目）

例：`./build/{branch}/data/{sheet}.json`

## 导出流程

1. 主窗口菜单 → **文件 → 导出数据**
2. 选格式
3. 是否启用"导出前验证"（推荐开）
4. 点 **导出** → 完成

## 导出前验证

启用后，导出前会跑一遍**验证规则 DSL**（详见[[验证规则DSL]]）：

- error 级别失败 → **阻断导出**，给出错误清单
- warning 级别失败 → 弹提示，让你选"继续 / 取消"

> [!IMPORTANT]
> 强烈建议生产构建保持"验证通过才导出"——否则坏数据进游戏，定位起来更难。

## 导出范围

| 范围 | 说明 |
|------|------|
| 当前 sheet | 只导出激活页签 |
| 当前工程所有 sheet | 一键全导 |
| 自选 sheet | 勾选要导出的子集 |
| 按文件夹 | 把多个工程的同名 sheet 合并导出（高级） |

## C# Data Class 导出细节

```csharp
[MessagePackObject]
public class TalentConfig {
    [Key(0)] public int Id { get; set; }
    [Key(1)] public string Name { get; set; }
    [Key(2)] public int Level { get; set; }
    [Key(3)] public List<RewardItem> Rewards { get; set; }
}
```

支持：

- 列名 → 字段名（驼峰转 PascalCase）
- 类型推断（int / string / float / List<T> / Dictionary<K,V>）
- 嵌套类（CT 多数据列自动生成嵌套类型）
- 跨表引用 → 用 ID 引用，不展开

## Protobuf 导出细节

同时输出：

- `.proto` 文件 → 拿去给后端 / 多端共用
- `.bin` 文件 → 实际数据
- 跨语言：C# / Go / Java / Python / TypeScript 等都能解码

需要在设置里指定 protobuf 版本（proto2 / proto3，默认 proto3）。

## 二进制三种怎么选

| 格式 | 选它的时机 |
|------|-----------|
| Bytes（JSONB） | 只在 C# 端读，跟现有工具链无冲突 |
| Binary（MessagePack） | 跨平台、跨语言、生态成熟（MessagePack-CSharp / msgpack-python） |
| Protobuf | 已有 .proto schema、需要严格 schema、跟后端共用 |

新项目推荐 **MessagePack**——平衡好（性能 / 大小 / 兼容）。

## 性能基准

| 格式 | 10000 行 sheet | 输出大小 |
|------|----------------|---------|
| JSON | 0.8s | 2.4 MB |
| YAML | 1.2s | 2.8 MB |
| Bytes | 1.0s | 1.4 MB |
| MessagePack | 1.0s | 1.3 MB |
| Protobuf Binary | 1.5s | 1.2 MB |
| C# 类 | 0.5s | 80 KB（仅声明） |

## 注意事项

> [!TIP]
> 大项目建议在 CI 里跑批量导出——`scripts/` 下提供命令行导出 API（详见高级文档）。每次 commit 自动导出所有格式，引擎端直接拉构建产物。

> [!WARNING]
> 改了导出路径后不会自动清旧文件——构建脚本里加上"清旧 → 导新"步骤。
