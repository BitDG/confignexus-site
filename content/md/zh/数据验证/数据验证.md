# 数据验证

表填完，点导出——报错。回去找，发现 ID 重复了、有个字段名有空格、引用了已删除的物品 ID。一个个格子翻，翻几百行，找到修完再导出，又报新的错。数据验证就是把这一轮"导出→报错→找→改"压缩成"填表时实时标红"：错的格子立刻变红，悬停就看到原因，点验证日志直接跳到那一格。

> [!tip]
> 两层校验同时在跑：**基础校验**（ID 重复、字段名不合法、数组格式等）软件自动查，不用配；**DSL 规则校验**由你在表头验证规则行写声明（如 `required`、`range(1,100)`），按你的业务规则查。

## 三步上手

### 第 1 步：确认表格有正确的表头结构

ConfigNexus 的标准表头是 5 行，验证器依赖这个结构识别"哪些是规则、哪些是数据"：

| 行号 | 角色 | 示例内容 |
|-----|------|---------|
| 第 1 行 | 英文字段名 | id, name, type, price |
| 第 2 行 | 中文字段名 | 编号, 名称, 类型, 价格 |
| 第 3 行 | 数据类型 | int, string, int, float |
| 第 4 行 | 描述 | 唯一ID, 物品名, 物品分类, 购买价格 |
| 第 5 行 | **验证规则** | required, required&&len(1,50), enum(1,2,3), range(0,9999) |
| 第 6 行起 | 数据 | 1001, 铁剑, 1, 100.5 |

> [!note]
> 导入演示工程后可以直接看到这个结构。如果你的表头行数不一样，可以在**设置 → 导出配置**里调整各行角色对应的行号。

### 第 2 步：在验证规则行写规则

在第 5 行（验证规则行），给需要约束的列填写 DSL 规则：

```
A 列 (id):     required
B 列 (name):   required&&len(1,50)
C 列 (type):   required&&enum(1,2,3)
D 列 (price):  range(0,9999)
E 列 (ref_id): ref(ItemConfig@id)
```

不需要约束的列留空就行，基础校验还是会跑。DSL 规则详见[[验证规则DSL]]。

### 第 3 步：跑验证、看结果、修错

点菜单栏**「数据验证」**按钮，系统遍历所有工作表、读规则、对每个数据格执行校验：

video:Res/zh/videos/数据验证.webm|点数据验证 → 结果显示在验证日志 → 点条目跳转到错误格子

验证结果在**日志面板 → 验证页签**里：

- 点错误条目 → 直接跳到对应格子
- 每条错误显示具体违反了哪条规则
- 修完一批后重跑，确认错误数量递减

> [!tip]
> 不用等手动跑——填表时**实时标红**已经在跑基础校验（比如 ID 重复立刻变红）。手动跑一次是为了同时触发跨表引用（ref/enum_ref）的批量校验。

## 基础校验（无需配置，自动跑）

| 检查项 | 触发条件 | 示例 |
|-------|---------|------|
| ID 唯一性 | A 列值重复 | A5=1001, A6=1001 → 报错 |
| 字段名唯一性 | 第 1 行同名（大小写敏感） | A1=id, C1=id → 报错 |
| 字段名合法性 | 含空格、中文、连字符等 | `my-name`、`等级`、`level price` → 报错 |
| 字典格式 | `List&lt;Dictionary&gt;` 类型格式不对 | `{1:100}` 而非 `[{1:100}]` → 报错 |
| 数组格式 | `int[]`/`string[]` 格式不对 | `1,2,3` 而非 `[1,2,3]` → 报错 |
| int 溢出 | 数据类型为 `int` 但值超出范围 | `9999999999` → 报错（改用 `long`） |

> [!note]
> 字段名以「忽略列符号」（设置 → 导出配置里配，默认 `_`）开头的列跳过字段名合法性检查，但仍参与唯一性检查。

## 导出前阻断

**有 error 时阻断导出，warning 不阻断**（但弹提示）：

- 阻断（error）：ID 重复、`required`/`unique`/`ref`/`enum_ref` 违反
- 放行但提示（warning）：`range`/`len`/`regex` 违反

建议勾选「导出前验证」（导出面板里有），有错直接拦在导出前。

## 注意事项

> [!warning]
> - `ref`/`enum_ref` 需要被引用的表在项目里打开。引用外部工程里的表，先通过**外部引用源**挂进来（详见[[外部引用源]]）。
> - 验证器遇到 A 列（ID 列）空值时会停止扫描后续行——认为那行之后没有有效数据。A 列必填校验因此不单独展示（空 A 直接截断）。
> - 实时标红只读当前编辑状态；手动点「数据验证」才会同时触发所有工作表的跨表引用校验。

### 完整 DSL 规则说明

| 规则 | 语法 | 说明 |
|------|------|------|
| 必填 | `required` | 字段不能为空 |
| 数值区间 | `range(min,max)` | 值必须在 min~max 之间 |
| 枚举 | `enum(a,b,c)` | 只能是这几个值 |
| 字符长度 | `len(min,max)` | 字符串长度限制 |
| 正则匹配 | `regex(pattern)` | 值必须匹配正则 |
| 唯一性 | `unique` | 该列值不能重复（仅数据区） |
| 跨表引用 | `ref(表名@列名)` | 值必须在另一张表存在（异步） |
| 枚举引用 | `enum_ref(表名@列名)` | 合法值动态来自另一张表（异步） |

规则组合用 `&&`，全部通过才合法：

```
required&&range(1,999)
required&&len(1,20)&&regex(^[a-z_]+$)
```

列表元素验证：列数据类型为 `list<int>` / `list<string>` 等时，规则自动拆解到每个元素上：

```
列类型: list<int>    规则: range(1,100)
值: [1,50,200]  → 元素 [2]: 数值 200 不在范围 [1, 100] 内
```

### 验证区域说明

每个工作表的验证范围：
- 起始列：A 列；起始行：数据起始行（默认第 6 行）
- 结束范围：到有效数据的最后一行和最后一列
- **ID 终止**：A 列遇到空值时停止验证（认为后续不是有效数据行）

### 最小规则集（复制即用）

```
A 列 (主键 int):       （留空，ID 重复由基础规则自动检查）
B 列 (字符串名):       required&&len(1,50)
C 列 (整数范围):       range(1,3)
D 列 (整数/浮点):      range(0,99999)
E 列 (比例):           range(0,1)
F 列 (字符串数组):     （留空，数据类型 string[]，格式由基础规则校验）
G 列 (字典):           （留空，数据类型 List&lt;Dictionary&lt;int,int&gt;&gt;，基础规则校验）
H 列 (业务编码):       regex(^[A-Z]{3}_\d{4}$)
I 列 (布尔):           （留空，数据类型 bool，基础规则校验，接受 true/false/0/1/yes/no）
J 列 (字符串枚举):     enum(weapon,armor,item)
K 列 (可空说明):       len(0,200)
```

### 与导出设置的协同

| 导出设置项 | 验证模板做法 | 效果 |
|-----------|------------|-----|
| 忽略列（按符号 `_` 前缀） | 字段名以 `_` 前缀命名（如 `_internal`） | 该列不导出，验证规则可置空 |
| 忽略列（按表头颜色） | 给该列第 1 行表头涂指定颜色 | 同上 |
| 忽略页签（按符号或颜色） | 整张内部表加 `_` 前缀或染色 | 该表不导出，仍可参与本地验证 |
| CSV 分隔符 | 数组/字典列使用 `[a,b,c]`/`[{1:10}]` 而非裸逗号 | 避免 CSV 导出时与分隔符冲突 |

### 自定义规则扩展

除 DSL 规则外，也可通过代码注册自定义验证函数（适合有程序员支持的项目）：

```javascript
window.validator.config.customRules = [
  {
    validate: (value, cellConfig) => {
      if (cellConfig.type === 'int' && value % 2 !== 0) {
        return '此列只允许偶数';
      }
      return true; // 通过
    }
  }
];
```

### 跨表引用验证说明

`ref()` 和 `enum_ref()` 支持跨工作表验证：

```
场景：物品表的 type 字段引用类型配置表

物品表 验证行 C 列:  ref(TypeConfig@id)
  → 系统自动查找名为 "TypeConfig" 的工作表
  → 读取其 "id" 列的所有值
  → 验证当前列的每个值是否在该集合中
```

跨表索引在点「数据验证」时自动注册，不需要手动操作。被引用的表必须在同一项目内打开，或通过外部引用源挂进来。
