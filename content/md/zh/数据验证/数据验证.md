# 数据验证

确保配置表数据的正确性和完整性。支持基础格式验证和 DSL 规则验证两层校验机制。

## 验证类型总览

### 基础验证（自动）

| 验证类型 | 说明 | 示例 |
|---------|------|------|
| ID 唯一性 | A 列的 ID 不能重复 | A5=1, A6=1 → 报错 |
| 字段名唯一性 | 第 1 行（英文字段名行）同一名字只能出现一次；大小写敏感、空白字段名跳过、被忽略列也参与 | A1=id, C1=id → 报错；A1=id, C1=ID → 不报 |
| 字段名命名风格 | 英文字段名必须符合变量名规则 `^[A-Za-z_][A-Za-z0-9_]*$`，否则导出 C# / proto / JSON 时会出错。**白名单**：以「设置 → 导出配置 → 忽略列符号」开头的字段名（这些列本身不导出）会跳过此检查；但字段名唯一性仍然参与 | `itemId` ✓，`_internal` ✓；`1id`、`my-name`、`等级`、`level price` → 报错；如果忽略列符号配成 `#`，则 `#tmp` 跳过格式检查 |
| 字典格式 | `List<Dictionary>` 类型必须为 `[{key:value}]` | `[{1:100}]` ✓，`{1:100}` ✗ |
| 数组格式 | `int[]`/`float[]`/`string[]` 类型必须为 `[x,y]` | `[1,2,3]` ✓，`1,2,3` ✗ |
| int 溢出 | 数据类型行写 `int` 时，值必须在 int32 范围 `[-2147483648, 2147483647]` 内 | `9999999999` → 报错；超大数值请把类型改成 `long` |

### DSL 规则验证（验证行配置）

在表格结构的**验证行**中写入 DSL 规则，系统自动执行校验：

| 规则 | 语法 | 状态 | 示例 |
|------|------|------|------|
| 必填 | `required` | ✅ 已启用 | 字段不能为空 |
| 数值区间 | `range(min,max)` | ✅ 已启用 | `range(0,100)` — 值必须在 0~100 之间 |
| 枚举 | `enum(a,b,c)` | ✅ 已启用 | `enum(warrior,mage,archer)` — 只能选这三个值 |
| 字符长度 | `len(min,max)` | ✅ 已启用 | `len(1,50)` — 字符串长度 1~50 |
| 正则匹配 | `regex(pattern)` | ✅ 已启用 | `regex(^[A-Z]{3}_\d+$)` — 匹配格式 |
| 唯一性 | `unique` | ✅ 已启用 | 该列值不能重复（仅数据区，表头行不算） |
| 跨表引用 | `ref(表名@列名)` | ✅ 已启用（异步） | `ref(TypeConfig@id)` — 值必须在另一张表存在 |
| 枚举引用 | `enum_ref(表名@列名)` | ✅ 已启用（异步） | `enum_ref(TypeConfig@id)` — 从另一张表取枚举 |

> 📌 `ref` / `enum_ref` 工作原理：点「数据验证」时，系统会把所有工作表的列值自动注册到主进程跨表索引（见 [validator.js validateCurrentSheet Phase 0](../../../validator.js)），然后批量查询每条 `ref()` 候选，未命中的报错。
>

#### 规则组合

多条规则用 `&&` 连接，全部通过才算合法：

```
required&&range(1,999)          → 必填且在 1~999 之间
required&&len(1,20)&&regex(^[a-z_]+$)  → 必填、长度 1~20、只含小写和下划线
```

#### 列表元素验证

当列的数据类型是 `list<int>`、`list<string>` 等列表类型时，规则会自动**拆解到每个元素**上验证：

```
列类型: list<int>    规则: range(1,100)
值: [1,50,200]  → 元素 [2]: 数值 200 不在范围 [1, 100] 内
```

## 打开方式

点击菜单栏「数据验证」按钮，或通过快捷键触发。验证结果显示在日志查看器的验证页签中。

## 验证区域

每个工作表的验证区域基于表格结构配置：
- **起始列**：A 列
- **起始行**：数据起始行（由表格结构定义，默认第 5 行）
- **结束范围**：到有效数据的最后一行和最后一列
- **ID 终止**：A 列遇到空值时停止验证（认为后续不是有效数据行）

## 工作流演示

### 步骤 1：配置表格结构

确保表格有正确的行结构。默认 5 行表头：

| 行号 | 角色 | 示例 |
|-----|------|------|
| 第 1 行 | 英文字段名 | id, name, type, price |
| 第 2 行 | 中文字段名 | 编号, 名称, 类型, 价格 |
| 第 3 行 | 数据类型 | int, string, int, float |
| 第 4 行 | 描述 | 唯一ID, 物品名, 物品分类, 购买价格 |
| 第 5 行 | 验证规则 | required, required&&len(1,50), enum(1,2,3), range(0,9999) |
| 第 6 行起 | 数据 | 1, 铁剑, 1, 100.5 |

### 步骤 2：编写验证规则

在验证行中为需要校验的列填写 DSL 规则：

```
A 列 (id):     required
B 列 (name):   required&&len(1,50)
C 列 (type):   required&&enum(1,2,3)
D 列 (price):  range(0,9999)
E 列 (ref_id): ref(ItemConfig@id)
```

### 步骤 3：执行验证

点击「数据验证」按钮，系统会：
1. 遍历所有工作表
2. 读取每张表的验证行规则
3. 对每个数据单元格执行对应规则
4. 将错误输出到日志查看器

### 步骤 4：查看与修复

验证结果在日志面板的「验证」页签中显示：
- 📍 点击错误条目可跳转到对应单元格
- 🔴 错误级别：显示具体的规则失败原因
- 💡 修复建议：每条错误附带解决方案

## 跨表引用验证

`ref()` 和 `enum_ref()` 支持跨工作表验证：

```
场景：物品表的 type 字段引用类型配置表

物品表 验证行 C 列:  ref(TypeConfig@id)
  → 系统自动查找名为 "TypeConfig" 的工作表
  → 读取其 "id" 列的所有值
  → 验证当前列的每个值是否在该集合中
```

## 自定义规则扩展

除 DSL 规则外，还可通过代码注册自定义验证函数：

```javascript
window.validator.config.customRules = [
  {
    validate: (value, cellConfig) => {
      if (cellConfig.type === 'int' && value % 2 !== 0) {
        return '此列只允许偶数';
      }
      return true; // 通过
    }
  }
];
```

| 第 4 行 | 描述 | 主键 | 物品名 | 类型(1-3) | 售价 | 折扣 | 标签集 | 键值属性 | 业务编码 | 是否启用 | 分类 | 备注 | 指向 TypeConfig.id |
| 第 5 行 | **验证规则** | （ID 重复自动）| `required&&len(1,50)` | `range(1,3)` | `range(0,99999)` | `range(0,1)` | （`string[]` 自动数组格式） | （`List<Dictionary>` 自动字典格式） | `regex(^[A-Z]{3}_\d{4}$)` | （`bool` 自动类型） | `enum(weapon,armor,item)` | `len(0,200)` | `ref(TypeConfig@id)` |
| 第 6 行起 | 数据 | 1001 | 铁剑 | 1 | 100 | 0.8 | `[a,b,c]` | `[{1:10},{2:20}]` | WPN_0001 | true | weapon | 普通武器 | 1 |

> 模板还附带 **TypeConfig** 工作表（id=1/2/3 对应 weapon/armor/item），主表 L 列的 `ref(TypeConfig@id)` 在每次验证开始时会自动注册其 id 集合，第 13 行 L 列填 99 → 触发"引用不存在"。

> 关键约定（**数据类型行只写纯类型，所有约束放验证行**）：
> - **C 列**：数据类型写 `int`，范围约束 `range(1,3)` 写在验证行（不要再用 `int|1|3` 这种把验证嵌进类型的写法）。
> - **F 列** 必须用 `string[]` 而**不是** `list<string>`——基础数组格式只识别 `xxx[]` 类型（见 [validator.js:36](../../../validator.js#L36)）。
> - **I 列** bool 接受 `true / false / 0 / 1 / yes / no` 六种值，其它都报错。
> - **K 列** 直接写 `string`（不用 `string?`）——可空语义靠**不写** `required` 表达。

### 与导出设置的协同

| 导出设置项 | 验证模板做法 | 效果 |
|-----------|------------|-----|
| 忽略列（按符号 `_` 前缀） | 字段名以 `_` 前缀命名（如 `_internal`） | 该列不导出，验证规则也可置空 |
| 忽略列（按表头颜色） | 给该列第 1 行表头涂上配置的颜色 | 同上 |
| 忽略页签（按符号或颜色） | 整张内部表加 `_` 前缀或染色 | 该表不导出，仍可参与本地验证 |
| CSV 分隔符 | 数组/字典列使用 `[a,b,c]` / `[{1:10}]` 而非裸逗号 | 避免 CSV 导出时与分隔符冲突 |
| 多格式导出（JSON/CS/Binary/...）| 可空字段：数据类型写 `string`（不写 `?`），验证行只放 `len(0,200)`、不写 `required` | 序列化端可输出 `null`，避免误报 |

### 推荐的最小验证规则集（按列复制即可）

```
A 列 (主键 int):       （留空，ID 重复由基础规则自动检查）
B 列 (字符串名):       required&&len(1,50)
C 列 (整数范围):       range(1,3)                  # 数据类型行写 int
D 列 (整数/浮点):      range(0,99999)              # 数据类型行写 float
E 列 (比例):           range(0,1)
F 列 (字符串数组):     （留空）                    # 数据类型 string[]，格式由基础规则校验
G 列 (字典):           （留空）                    # 数据类型 List<Dictionary<int,int>>，格式由基础规则校验
H 列 (业务编码):       regex(^[A-Z]{3}_\d{4}$)
I 列 (布尔):           （留空）                    # 数据类型 bool，由基础规则校验（接受 true/false/0/1/yes/no）
J 列 (字符串枚举):     enum(weapon,armor,item)

```

### 使用步骤

1. 在欢迎页点击「打开测试模板」直接载入 `数据验证测试.cnx`，或新建工作表按上表填入第 1~5 行表头与验证规则。
2. 复制本节第 2~14 行测试数据到第 6 行起。
3. 创建 **TypeConfig** 工作表并填入示例数据。
4. 「设置 → 导出配置」：把忽略列符号设为 `_`（或自定义颜色）。
5. 点击菜单栏「数据验证」按钮，日志查看器的「验证」页签会列出全部 14 处错误。
6. 修复一类错误后重新验证，确认错误数量递减——**模板的目标就是让每一类错误都至少触发一次**。
