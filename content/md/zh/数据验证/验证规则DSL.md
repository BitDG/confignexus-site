# 验证规则 DSL

ID 列填了重复 ID 你不知道，枚举列填了不存在的值你不知道，跨表引用填了个已删除的 ID 更不知道——直到导出后程序报错、或者游戏运行时崩了才发现。验证规则 DSL 就是干这个的：在表头验证规则行写一小段声明（比如 `required`、`unique`、`ref(item@id)`），整列就被纳入实时检查，填错立刻标红，不用等到导出才发现。

> [!tip]
> DSL（Domain-Specific Language，领域特定语言）这里就是一小段"校验声明字符串"——写在表头、简洁、可版本控制、能复制粘贴。不是图形界面拼规则，就是字面上那几个字。

## 8 条内置规则

| 规则 | 语法示例 | 作用 |
|------|----------|------|
| `required` | `required` | 必填，空格子标红 |
| `unique` | `unique` | 整列唯一，防重复 ID 必备 |
| `range(min, max)` | `range(1, 100)` | 数值必须在区间内 |
| `enum(a, b, c)` | `enum(DAILY, WEEKLY, MONTHLY)` | 只允许这几个值（写死的枚举） |
| `enum_ref(表名@列名)` | `enum_ref(item@id)` | 合法值动态来自另一张表的某列 |
| `len(min, max)` | `len(1, 50)` | 字符串长度限制 |
| `regex(pattern)` | `regex(^[A-Z]+$)` | 正则表达式匹配 |
| `ref(表名@列名)` | `ref(item@id)` | 跨表引用完整性——值必须在对面表存在 |

## 组合规则：`&&`

多条规则用 `&&` 串联，从左到右依次校验，全过才算合法：

```
required && range(0, 100)
```

意思：先必填（空了直接标红），再检查 0-100（超出标红）。

```
required && unique && len(3, 20) && regex(^[a-z_]+$)
```

意思：必填 + 全表唯一 + 长度 3-20 + 只含小写字母和下划线，四条全过才合法。

## 四个最常用的示例

### 主键 ID 列

```
required && unique && range(1000, 99999)
```

必填、不重复、在给定区间——复制这一行就能用。

### 枚举类型列（值写死）

```
required && enum(DAILY, WEEKLY, MAIN, SIDE)
```

只能填这四个值，写别的就标红。

### 外键列（引用另一张表）

```
required && ref(item@id)
```

填的 ID 必须在 `item` 表的 `id` 列里存在，外键完整性自动保证。

### 动态枚举列（合法值来自另一张表）

```
enum_ref(condition_type@id)
```

`condition_type` 表里加了新行，这列的合法值集合自动跟着变——不用手动维护枚举列表。

## 在哪里写规则

表头的**验证规则行**（默认第 5 行，行角色为 `validation`）。哪列需要验证就在该列的第 5 行格子里写对应规则字符串。

> [!tip]
> 不知道哪一行是验证规则行？导入演示工程后看第 5 行的颜色标注，或右键列头 → CT 属性 → 查看当前验证规则。

## 错误是怎么显示的

- **实时标红**：违反规则的格子编辑时立即变红，不用等跑验证
- **悬停提示**：鼠标移到红格，tooltip 显示具体违反了哪条规则
- **验证日志**：菜单 → 验证日志，列出所有错误，**点行直接跳到对应格子**

## 导出前阻断

导出时（JSON / Protobuf 等）系统再跑一遍全表校验。**有 error 时阻断导出**（warning 不阻断）：

- 阻断（error）：`required` / `unique` / `ref` / `enum_ref` 违反
- 放行但弹提示（warning）：`range` / `len` / `regex` 违反

> [!tip]
> 想把所有规则都当 error 处理？设置 → 数据验证 → 关掉「宽松模式」。

## 解析器特性

- **括号感知**：`regex(\(a\|b\))` 不会被外层 `&&` 误拆
- **空白容忍**：`required  &&  range( 0 , 100 )` 跟 `required&&range(0,100)` 等价
- **大小写敏感**：规则名小写，参数原样保留

## 注意事项

> [!warning]
> `ref` / `enum_ref` 需要引用的那张表已经在项目里打开。如果被引用的表不在项目内，需要通过**外部引用源**挂进来（详见[[外部引用源]]）。

> [!note]
> 老教程"数据验证"里讲的图形界面配规则是 v0.0.1 时代的旧方式，v0.0.2 起统一改为 DSL 字符串。老配置升级时自动转 DSL，不用手动改。
