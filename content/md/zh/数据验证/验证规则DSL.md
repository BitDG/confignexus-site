# 数据验证规则 DSL

★ 商店标"全新"的功能：在表头一行写一段规则字符串，整列就被纳入验证。错误实时标红，点验证日志能直接跳转到出错单元格。

不是图形界面拼规则，而是"声明式规则字符串"——简洁、可版本控制、能复制粘贴。

## 8 条内置规则

| 规则 | 语法示例 | 说明 |
|------|----------|------|
| `required` | `required` | 必填校验，空单元格标红 |
| `unique` | `unique` | 整列唯一性，主键防重必备 |
| `range(min, max)` | `range(1, 100)` | 数值区间约束 |
| `enum(a, b, c)` | `enum(DAILY, WEEKLY, MONTHLY)` | 枚举值（写死的） |
| `enum_ref(表名@列名)` | `enum_ref(item@id)` | 枚举值（动态从另一张表的某列拿） |
| `len(min, max)` | `len(1, 50)` | 字符串长度区间 |
| `regex(pattern)` | `regex(^[A-Z]+$)` | 正则表达式 |
| `ref(表名@列名)` | `ref(item@id)` | 跨表引用完整性——填的值必须在对面表里存在 |

## 组合规则：`&&`

任意串联，从左到右依次校验：

```
required && range(0, 100)
```

意思：先必填（空了直接标红），再 0-100（超出范围标红）。

```
required && unique && len(3, 20) && regex(^[a-z_]+$)
```

意思：四个条件全过才算合法（必填 + 全表唯一 + 长度 3-20 + 小写字母下划线）。

## 实战示例

### 玩家 ID 列（典型主键）

```
required && unique && range(1000, 99999)
```

### 任务类型列（固定枚举）

```
required && enum(DAILY, WEEKLY, MAIN, SIDE)
```

### 奖励物品 ID 列（外键到物品表）

```
required && ref(item@id)
```

效果：填的 ID 必须在 `item` 表的 `id` 列里存在，否则标红。

### 关卡解锁条件列（外键 + 枚举）

```
enum_ref(condition_type@id)
```

效果：合法值动态来自 `condition_type` 表的 `id` 列——`condition_type` 加新行后，这一列的合法值集合自动变。

### 邮件 / 公告标题（长度 + 必填）

```
required && len(1, 50)
```

## 在哪写规则

每个 CT 列的表头第二行（验证规则行）。如果项目没启用 CT 列，普通列也能在 schema 配置里挂规则。

## 错误显示

- **实时标红**：违反规则的单元格立即变红（编辑时就提示，不用等导出）
- **悬停提示**：鼠标移到红色单元格，tooltip 显示具体违反了哪条规则
- **验证日志**：菜单 → 验证日志，列出所有错误。**点行直接跳到对应单元格**

## 导出前阻断

导出时（JSON / Protobuf 等）系统会再跑一遍全表校验。**有 error 时阻断导出**（warning 不阻断）：

- error：`required` / `unique` / `ref` / `enum_ref` 失败 → 阻断
- warning：`range` / `len` / `regex` 失败 → 允许导出但弹提示

> [!TIP]
> 想强制把所有规则当 error？设置 → 数据验证 → "宽松模式"关掉。

## 解析器特性

- **括号感知**：`regex(\(a\|b\))` 不会被外层 `&&` 误拆，因为解析器知道哪个括号属于 regex
- **空白容忍**：`required  &&  range( 0 , 100 )` 跟 `required&&range(0,100)` 等价
- **大小写敏感**：规则名小写，参数原样保留

## 注意事项

> [!WARNING]
> `ref` / `enum_ref` 需要另一张表已经加载到项目里。如果另一张表不在项目内，要通过**外部引用源**挂进来（详见教程《外部引用源》）。

> [!NOTE]
> 之前老教程"数据验证"讲的是用 UI 配置规则——那是 v0.0.1 时代的旧方式。v0.0.2 起统一改为 DSL 字符串。老配置在升级时自动转 DSL，不用手动改。
