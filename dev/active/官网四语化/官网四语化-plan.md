# 官网四语化 · Plan

## 大哥摘要（先看这段）

现在官网全是中文。这次让它跟软件一样支持**中 / 英 / 日 / 韩**四种语言：

- 右上角会多一个**语言切换按钮**，点一下整站语言就变（首页、功能、下载、文档页的菜单和正文都跟着变）。
- 别人第一次打开网站，会**自动按他浏览器的语言**显示（认不出就给中文）；他手动选过一次之后，网站会**记住**他的选择。
- 文档正文用的是软件里**已经翻译好**的英日韩教程。软件里没翻译到的那几篇，文档页会照常列出来，但点进去会顶上挂一行"⚠ 该教程暂无 X 语言翻译，以下为中文原文"，下面接中文内容——不会出现"菜单有、点进去空白"的情况。

不用担心动到你现有的东西：中文是默认/兜底语言，所有改动都是"在原中文上叠加翻译"，关掉 JS 也还是能看到完整中文站。

**验收看这里**：上线后打开网站，右上角点"EN / 日 / 한 / 中"任意一个，整页文字立刻切换；刷新后语言保持；把浏览器语言设成日语后用无痕窗口打开，首页自动显示日文。

## 目标

让官网四语可用，且可验证：

1. **语言切换可见可用**：四个页面右上角都有语言切换器；点击后页面文案（导航、按钮、标题、正文、footer、`<title>`、meta description）切到对应语言。验收：浏览器里点切换器，肉眼看到全页文字改变。
2. **首访自动识别 + 记忆**：无历史选择时按 `navigator.languages` 映射到 zh/en/ja/ko（认不出回退 zh）；手动选择写入 localStorage，刷新/重开后保持。验收：清空 localStorage、把浏览器语言设为各语言后无痕打开，命中对应语言；手动切一次后刷新仍是手动选的那个。
3. **文档四语 + 缺失回退**：文档页侧栏按语言显示分类/篇目标题；正文优先用该语言翻译，缺失则显示中文并在顶部挂"暂无翻译"提示条（正文容器 `lang="zh-CN"`）。验收：英文模式下，已翻译篇目显示英文正文；未翻译篇目顶部出现提示条 + 中文正文。
4. **深链不破**：features 页功能卡片点进去仍能跳到对应教程（任意语言下都不报错）。验收：英文模式点功能卡片，正确定位到对应文档篇目。
5. **不退化**：禁用 JS 时仍显示完整中文站；类型/构建脚本 `node build-docs.mjs` 能跑通生成数据文件。

## 非目标（本次不做）

- 不做 `/en/ /ja/ /ko/` 独立静态子目录页与 hreflang/sitemap（即不为非中文做强 SEO；客户端同一 URL 切换，SEO 以中文为主——见下方"风险"，如需强 SEO 再单独立项）。
- 不新翻译任何文档正文：英日韩正文只用软件源码里**已存在**的翻译，缺的就回退中文，本次不补译。
- 不启用首页开场俄罗斯方块动画（见"风险"第 4 条：它当前根本没被引入）。本次只把它的文案顺手四语化，不改变"是否播放"的现状。
- 不重构现有 CSS / 卡片光斑 / Markdown 渲染逻辑，只做必要的挂钩。

## 实施步骤

1. **建 i18n 基座 `i18n.js`**（每页 `<head>` 引入，先于页面脚本）
   - head 内只做轻量的**语言检测**：localStorage `cn_lang`（校验合法值）→ `navigator.languages` 映射 → 回退 `zh`；设 `document.documentElement.lang` 与 `window.CN_LANG`；非 zh 时给 `<html>` 加 `i18n-pending` 类（CSS 先隐藏可翻译区，避免中文闪一下）。
   - DOM 就绪后：注入右上角语言切换器到 `.nav-links`、`applyMarketingI18n()` 翻译本页、移除 `i18n-pending`。
   - 切换语言：写 localStorage → `location.reload()`（首版用刷新，状态最少、标题/字体/文档一致；用 sessionStorage 标记避免开场动画重播——虽当前未启用，先留好钩子）。
   - 验证：四页都出现切换器；切换后 `document.documentElement.lang` 变化、文案变化。

2. **营销页字典 + 打标**（index / features / download）
   - 给可翻译元素加 `data-i18n="key"`；默认 `textContent` 注入，**仅白名单富文本 key**（含 `<span>/<br>` 的，如首页大标题）用 `innerHTML`。
   - 字典 `MARKETING_I18N[lang][key]`：四语 key 必须齐全，构建/运行时缺 key 报警不静默留中文。
   - `<title>` / `meta[name=description]` 按语言设置。
   - 验证：三页逐语言切换，无残留中文（除有意保留的品牌名 ConfigNexus）。

3. **重写 `build-docs.mjs`：四语数据 + 资源 + 校验**
   - 扫 `md/zh|en|ja|ko` **真实目录**，生成 `window.DOCS = { zh:{key:md}, en:{...}, ja:{...}, ko:{...} }`（key 用各语言自己的相对路径）。
   - 复制 `welcome/Res/{en,ja,ko}` → 站点 `docs/Res-{en,ja,ko}/`（zh 已存在）。
   - 维护**唯一 manifest**（稳定 ID → 每语言{分类标题、篇目标题、文件 key 或 null}）：build 时校验「manifest 引用的文件都存在」「真实目录里没有漏收录的文件」，不一致就在 console 报警。
   - 验证：`node build-docs.mjs` 跑通，打印四语篇数；docs-data.js 含四个语言键。

4. **改造 `docs.js`：canonical 结构 + 回退提示**
   - STRUCTURE 改成读 manifest 的**稳定 ID** 顺序；侧栏按 `window.CN_LANG` 渲染该语言的分类/篇目标题。
   - `show(id)`：解析稳定 ID → 当前语言文件 key；存在则渲染该语言正文；缺失则渲染中文正文 + 顶部"⚠ 暂无 X 语言翻译，以下为中文原文"提示条，正文容器置 `lang="zh-CN"`。
   - 媒体路径按当前语言改写 `Res/<lang>/` → `docs/Res-<lang>/`，加载失败回退 zh（沿用现有 onerror 思路）。
   - hash：安全 `decodeURIComponent`（非法 `%` 不抛错）；接受稳定 ID，同时把旧的中文 hash 作为**兼容别名**映射到稳定 ID。
   - 验证：四语切换侧栏与正文正确；未翻译篇目出现提示条；旧中文深链仍能打开。

5. **features.html 深链改稳定 ID**
   - 把功能卡片的 `docs.html#<中文编码>` 换成 `docs.html#<稳定ID>`（我控制此文件）；docs.js 兼容别名兜底旧链接。
   - 验证：各语言点功能卡片正确定位。

6. **intro.js 文案四语化**
   - `MUSINGS` / `REVEAL` 按 `window.CN_LANG` 取对应语言数组（不改变它"是否被引入/播放"的现状）。
   - 验证：代码层确认按语言取值；（动画当前未启用，无浏览器验收项，故此步不计入"UI 可观察验收"。）

7. **字体**：ja/ko 时动态加载 Noto Sans JP / KR（按 `window.CN_LANG` 注入 `<link>`），避免日韩字形回退难看。验证：日/韩模式字形正常。

## 边界情况

- localStorage 不可用 / 抛异常（隐私模式）→ try-catch，回退到仅检测、不持久化。
- `navigator.languages` 为空或含地区码（`zh-TW`/`en-US`）→ 取主语言前缀映射；`zh-*` 一律 zh。
- 非法 / 未知 hash（手敲、旧书签、非法 `%`）→ 安全解码失败则回退首篇，不白屏。
- 某语言整类为空（en/ja/ko 的 Python、扩展生态在软件里就是空的）→ 该分类下所有篇目走"缺失回退中文 + 提示条"。
- 富文本 key 翻译里误写标签 → 仅白名单 key 用 innerHTML，其余 textContent，避免注入/布局崩。
- 媒体资源某语言 404 → onerror 回退 zh 资源或显示占位（沿用现有图片/视频 onerror）。
- 禁用 JS → 看到完整中文站（HTML 默认即中文）。

## 风险与注意

1. **SEO 取舍（需大哥知晓）**：客户端同 URL 切换语言，对非中文的搜索引擎收录较弱（Google 不按 `#fragment` 区分内容页）。判断：维护者非程序员、站点小，客户端方案维护成本最低，故本次按此做、SEO 以中文为主。若日后非常看重英日韩自然搜索流量，再单独立项做静态子目录 + hreflang。**这条若你不认可，请在确认 plan 时说，会改成生成静态子目录页。**
2. **文档"中文混排"**：缺翻译篇目会在英/日/韩菜单下出现中文正文。已用顶部提示条 + 正文 `lang="zh-CN"` 明示，不静默混入。这是为了"菜单不空"的取舍；若你更想要"干脆只列已翻译篇目"（更干净但日韩很少），确认时告诉我。
3. **manifest 是手建的 35×N 映射**：稳定 ID + 每语言标题/文件名集中在一份 manifest，build 时自动校验防漏防错；但首次仍需我逐条对齐软件四语目录，是本任务最细的活。
4. **首页开场动画当前未启用**：`index.html` 只 `<script src="site.js">`，并未引入 `intro.js`，所以俄罗斯方块开场**实际没在跑**。本次按"维持现状"处理——只四语化它的文案，不擅自启用。若你本意是想让它跑起来，确认时说一声（属另一件事）。
5. **FOUC（文字闪烁）**：非中文用户首屏可能先看到中文再切换。用 `i18n-pending` 类先隐藏可翻译区缓解，但首屏会略有延迟。可接受。
